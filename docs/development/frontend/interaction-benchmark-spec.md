# Admin 交互原型产物规范（按风险选择验证深度）

> **用途**：为未确定、复杂或高风险的 Admin 前端任务提供可操作的验证资产；不规定永久 UI 布局、全景模块数、主题色或生产组件实现。流程详见 [原型与 AI 开发工作流](./interaction-benchmark-workflow.md)。模拟不代表已实现后端、真实安全或正式开发授权。

## 1. 场景与验证范围

- 先明确本次要验证的任务、参与角色、数据/权限范围、正常操作、错误/冲突、状态恢复和验收问题；只制作有实际价值的模块与路径。
- 跨模块数据联动、复杂表单、防重与不可逆操作、权限作用域及 `UNKNOWN` 等高风险恢复必须有可观察的完整行为；不是所有原型都必须覆盖整个平台，也不要求固定六模块、四主题或五条剧本。
- 已批准的小范围 UI 修改可以直接在正式代码中实现并回归，不重复原型。新增业务功能与后端接口须先更新正式业务合同，不通过原型自动立项。

## 2. 原型与正式界面的边界

- 可以使用单文件 HTML、局部真实 React-admin/MUI 组件或其他经任务允许的低成本载体。不得强制原型 DOM 1:1 复制组件库、附加第二套正式 UI 工程或为了原型建设重型工具链。
- 尽可能使用合适的真实交互语义、可读排版与状态展示。所有可点击的核心操作必须实际改变合成数据/可见状态或明确标识尚未实现；严禁静态成功 Toast 伪装完成。
- 对合成数据、故障注入、视口与主题切换、操作引导，可在**需要时**提供独立于业务界面的测试控件，避免验证说明污染实际业务界面。不强制 Studio Bar、固定 48px、高对比深色、右侧抽屉或指定剧本数量。
- 原型不得访问生产服务、真实凭据、service_role 或真实用户隐私数据；不模拟“已验证”的真实 RLS/RPC/MFA/WCAG 结果。不能通过原型按钮自动产生所有者签收。

## 3. 最低可审阅交付

1. 说明场景、入口、测试数据和适用业务合同；提供关键的「初始状态 → 操作 → 预期状态」及关键负向/恢复路径。
2. 展示加载、空数据、提交、取消、权限/冲突/网络错误及结果未知等**实际涉及**的状态；仅在该场景需跨模块联动时实现共享模拟状态。
3. 验证可读性、键盘可操作性、窄屏/缩放和 Theme 消费的适用部分。精确断点与色板由本次设计与用户反馈决定，不继承旧方案。
4. 交付简明「怎么体验」说明，放在对话、原型辅助面板或单独文档均可；不要把免责说明堆到最终业务界面。
5. 记录被评审的文件版本、问题、用户交互认可/视觉选择与单独施工授权。真正运行的测试才标 `PASS`，否则为 `NOT RUN` 或 `PENDING`。

## 4. 对接正式 React-admin

正式开发以当时的 React-admin/MUI 组件 API、最新业务合同、已确认体验和统一 Theme 为准，追求**行为、状态、安全语义与无障碍等价**，而不是照搬 HTML 节点、特定 Tabs/Drawer/Badge 或固定布局。原型代码、模拟身份、内存数据与故障注入控件不得误混入生产实现。
