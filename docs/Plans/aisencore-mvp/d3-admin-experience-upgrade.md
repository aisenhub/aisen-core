## 2. 设计方案候选：AisenCore Operator Studio

定位：**安静的高精度专业工作台**，视觉可对标顶级数字作品的排版、质感、秩序、动效与独创性，但不把展示型网站的夸张转场和 3D 卷入高频 Admin 工作。不是原 V6 的 1:1 复刻，也不继续展示未经设计的 RA 默认界面。

### 2.1 品牌与视觉基准（候选，须实物对比和用户确认）

- **色彩/材质**：石墨或深午夜蓝导航锚点，偏暖纸白/低对比雾灰工作区；克制的一种品牌强调（候选蓝紫/湖绿），语义上独立的成功绿、风险红、注意琥珀；层级主要由字体、空间和对齐建立，不靠五彩卡片。
- **字体/数字**：中文优先，真实 Windows Segoe UI/微软雅黑回退正确；正文候选 14–15px，页面标题 28–34px，数字/指标 24–40px，主次标题、表头、辅助元数据有清晰层级；UUID 与代码用等宽样式、缩略 + 复制/展开。
- **布局**：8px 基准间距尺度；桌面 232–256px 可折叠侧栏、约 60–72px 顶栏；内容横向舒适边距约 24–40px、宽屏合理 max-width；同一页面区块间距大于区块内间距。表格约 48–56px 行高只是初始候选，以真实密度测试为准。
- **框架适配**：仍以 react-admin 官方 Layout/Menu/List/Datagrid/Show/Create/Form/Query + MUI Theme/component variants/sx/styled 为技术基础；唯一 theme.ts 管理 Design Tokens，轻量共享 UI 组件只在真实复用时抽象，不引入另一个整套设计系统。
- **视觉原创性**：有品牌辨识度的工作台结构、真实可读的数据叙事、独立图标、精选状态表现与微交互；不直接复制 V6 球形装饰、霓虹点缀或其他获奖站模板。
- **对比方案**：UX-2 阶段用正式 MUI 组件渲染至少两个真实候选方向，每个至少有 Dashboard、产品列表、用户详情在 1440 与 390 CSS px 的截图，由所有者选定后冻结 tokens，而非根据文字描述自称「完美」。

### 2.2 八项强制设计检查

| CHECK | 必需完成的设计工作 | 验收方法 |
| --- | --- | --- |
| Typography | 中英混排统一字阶、权重、行高、数字等宽、长文本处理 | 实际 Windows 浏览器，标签/表格/弹窗无截断，层级清晰 |
| Whitespace | 页头、摘要、筛选、表格、详情与弹窗的节奏，大小屏空间策略 | 320/390/768/1024/1280/1440/1920 CSS px 不拥挤、不产生无意空洞 |
| Visual hierarchy | 页面标题→作用域→当前状态→主操作→次操作→技术细节 | 使用者 5 秒内能辨别“哪里、做什么、下一步” |

| Micro-interaction | hover、selected、focus、loading、disabled、提交反馈和 UNKNOWN | 键盘 Tab/Enter/Escape、错误焦点定位、失败后保留输入、即时回显 |

| Originality | 品牌风格、图标系统、数据摘要与任务驱动编排，不套壳 | 与旧 V6、默认 RA、经选择的高质量业界参照并排评审 |

## 3. 信息架构与逐页设计合同

**一级导航按用户任务**，而非数据库表全部平铺：

- **总览**：Dashboard（真实数据聚合/运营任务），产品。
- **产品运营（有范围）**：成员/用户、Pro 权益、发码与批次/兑换码安全摘要/核销、成员事件。
- **平台治理（全局）**：账号邮箱定位、管理员、平台限制、管理审计。

视口内明确显示“全平台/当前产品”，切换不改写服务器权限，跨产品过滤依然由服务端执行。菜单同级入口控制在合理密度，次要只读 Resource 可归组但不可失去可达性。

| 路由/业务 | 完成时的页面结构 | 特别检查 |
| --- | --- | --- |
| 登录 + MFA + Auth | 品牌登录壳、步骤状态、二维码绑定与恢复、明确安全退出 | AAL1 无法旁路、撤权后资源失效、过期会话、邮件恢复浏览器流程 |
| `/` Dashboard | 页面身份、真实范围摘要、关键指标、任务入口、最近安全活动；无数据明确下一步 | 指标由安全可用数据计算，禁止虚构累计/趋势 |
| `/products` | 状态汇总→产品主列/状态 Chip/创建/筛选→详情信息/受保护变更 | draft/active/suspended、产品暂停不误改成员、创建 RPC id 兼容 |
| `/users` `/memberships` | 精确邮箱定位→用户 360°（身份、成员、有效权益、事件）→产品成员详情/暂停恢复 | 安全 DEC-06 字段限制、未知邮箱不能误报“不存在”、left→suspended→left |
| `/grants` `/grant-new` | 用户/产品选择，30/365/自定义与永久模式，时间轴/到期/撤销呈现 | 模式字段互斥、幂等 request_id、UNKNOWN 结果核查、重复提交 |
| `/issue-codes` + batch/code/redemption | 发码→首响明文复制/TXT/CSV→批次安全概要与核销→撤销/UNKNOWN 恢复 | 不缓存明文、不二次获取、重放只读、找批次、撤销再新发为独立动作 |
| `/admins` `/restrictions` `/account-actions` | 关联用户身份、资格状态、目标与影响、必需原因确认 | 最后一名合格管理员保护、全局账号封禁与成员状态不同 |
| `/audit-logs` `/membership-events` | 操作时间线、关联用户与产品、筛选和结构化 before/after | 最小安全字段、无 code hash/秘密、真实筛选不扩权 |
| 所有页面状态 | 空/筛选无结果/Loading/401/403/409/503/超时/UNKNOWN/成功/移动 | 错误恢复明确，不以静态 toast 假装业务成功 |

**通用操作布局**：页头（名称/范围/动作）→必要摘要与筛选→数据主体（业务名称和状态优先，技术 ID 次要）→详情/关联关系；可复制的 UUID 收纳到详情；有根据的危险二次确认始终显示目标与后果。

- 顺序：产品→用户/成员→Pro→发码/核销→治理→审计事件。
- 用户选择而非裸 UUID、真实上下文联动、期限预设、首响 TXT/CSV、错误恢复与独立危险确认、详情相关记录与状态反馈。
- **通过标准**：所有获批业务路径在真实本地数据上走通；每页有正常、空、筛选空、加载、错误、受限、终态；不臆造 SaaS/后端能力。

### UX-5：视觉八维逐页精修及响应式
- 检查 typography/whitespace/hierarchy/color/motion/micro-interaction/responsive/originality，真实 Windows 渲染截图检查；测试视口：1920、1440、1280、1024、768、390、320 CSS px 与 200%/400% 缩放。
- 对照首批视觉基准、业界高标准的细节，同时优先保留 Admin 操作效率和低认知负担。
- **通过标准**：八维有具体截图/问题单/修复记录；无严重拥挤、错位、溢出、不可见焦点、状态颜色混淆、重动效问题。

### UX-6：真实浏览器业务/安全/无障碍验收
- 本地 GoTrue JWT+AAL2 与真实 PostgREST/RPC 运行 D3-UI-X01～X18 及新增用例：MFA 首绑、账号恢复、跨产品过滤、CRUD、用户 360、Pro 直授/续期、发码首响、UNKNOWN、最后管理员冲突。
- 验证持久存储/浏览器缓存/URL/构建产物无 secret/service_role/兑换码明文，不能把首次 Network 响应不可删除事实误认泄露；失网、401/403/409/503、全链路恢复。
- WCAG 2.2 AA、对比度、Tab/Enter/Escape/焦点返回/输入提示、prefers-reduced-motion、各断点回归；按真实记录衡量性能与代码拆包。
- **通过标准**：typecheck/lint/build、安全负例、D3-UI-X01～X18 和新增关键用例全部 PASS，所有 NOT RUN 明列，不能以模拟 E2E 替代。

### UX-7：有限轮次审美复审、用户签收与交接
- 三道关：① 完整截图/设计八维的逐页差距检查与修复；② 改完后的完整回归和安全/响应式检查；③ 用户实际操作与视觉审阅，记录反馈再整改并复测。
- 交付物：正常+异常/空态截图集、主题与组件使用指南、功能矩阵、fixture 使用/清理文档、真实 E2E 报告、已知问题与需真实平台后才可处理的边界。
- **交付定义**：无待解决 P0/P1 质量问题，八维维度审查都有证据，18 项指定 E2E 全过，业务与合成数据可长期体验，获得项目所有者实际确认；“完美”是设计追求，不能虚构数学意义的绝对零缺点或无限自评结论。
