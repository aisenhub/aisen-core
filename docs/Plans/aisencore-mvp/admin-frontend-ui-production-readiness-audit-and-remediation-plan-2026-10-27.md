## 0. 一页结论与使用方式

**判断**：Admin 已有完整的 React-admin/MUI 应用骨架、多资源列表/详情、登录 TOTP、运营命令、反馈工作台、安全确认及响应式加载状态；**尚不满足可宣布的生产级 UI 验收**。既有工程完成度曾被定性估计为约 75%–80%，该估计**不是经加权清单逐项验证的完成率，也不能当作发布准入率**。本次以逐项验收状态取代单一百分比。

**最关键的剩余工作**：（1）生产环境文案/身份/操作影响范围；（2）全业务成功与失败交互闭环；（3）非空数据的 SPA/移动端任务；（4）全站 WCAG 2.2 AA、八维视觉与真实所有者签收；（5）网络、数据规模、异常与完整证据。前端不能代替后端补出尚不存在的管理员角色、注销或实际业务权限；涉及这些能力先由领域合同批准后再实施 UI。

**验收纪律**：
- `CODED` 仅代表源代码存在；`PASS` 必须注明环境、数据、业务场景、测试命令与证据；`PARTIAL` 表示已验证但覆盖不完整；`FAIL` 是已复现问题；`NOT RUN` 表示未运行，不得写为故障已发生，也不得写为 PASS。
- **P0**：阻止生产/第一阶段准出，涉及信息泄漏、错误授权、操作结果不明、不可恢复的敏感损失或关键操作不可达；**P1**：关键业务、准确性、无障碍、端到端体验和完整生产质量缺口；**P2**：体验一致性、效率与可维护性改进。优先级是整改顺序，不等于已复现严重漏洞。
- 第一阶段使用**隔离本地环境、合成但代表性的产品/用户/成员/授权/反馈记录**做完整 Admin/Core 真实路径验收，需所有者视觉签收；第二阶段由 AisenLens 实际本地操作数据验收双端；第三阶段才是已单独授权的部署环境、真实 R2/SMTP/生产配置及正式发布。任何本地成功不得宣称已上线。

1. 基于 `App.tsx` 生成路由与操作矩阵，以本文件 `3` 为首版；逐页列出最多 3 个高频任务和危险动作。
2. 建立**隔离合成 QA 数据**：多产品、多账号、多成员状态、非空 Grant、过期/撤销、历史审计、反馈正文长度边界、0/1/2图、空页面和 20+ 行/多页。必要时使用现有隔离脚本，并实现显式清理；禁止触碰真实个人/生产数据。
3. 建立同一套场景证据模板：页面路由、数据规模、用户任务、是否有写入、环境、结果、截图、浏览器日志与 QA 清理状态。
4. 与当前 [第一阶段整改计划](./phase1-delivery-remediation-plan.md) 对齐；**不复制一份平行的业务 TODO**。

**准出**：矩阵无未归属的首阶段必做路由，至少每种关键业务状态都有可安全复现的合成样本；清理完成；所有者同意验收范围。**当前：NOT STARTED**。

### UI-G1｜Shell、导航、环境与全站状态（P1）

- 修正 `App.tsx` 环境写死文案；生产/预发/本地由可信构建配置决定，配置失效页不直接显示本地操作命令。
- 确认顶部范围 selector 是过滤器，不是授权控制；无效产品、超过100个产品、切换后当前页/筛选条件须稳定。
- 导航、Dialog/Overlay、Toast/Alert 与无权页面统一强调主要操作；路由懒加载不阻塞 AppBar/导航。
- 用主题 token 消除会改变视觉语义的重复局部色值，先做样例页面再全站应用；无必要不引入新组件系统。

**准出**：环境三态+配置错误两态独立截图，键盘能到达全部主入口；320–1440 视口无重要任务被遮挡或滚动陷阱；授权边界未变化。**当前：NOT STARTED**。

### UI-G2｜用户、产品和治理敏感操作（P0/P1）

- 用户详情：修正账号限制读取失败时绿色正常态（UI-03），清晰区分「未确定」「已封禁」「正常」，不把空结果和异常混为一谈。
- 封禁/解封/授撤管理员：核实身份与当前状态、**全平台影响**、操作结果的可见确认、409 保底拒绝；不让前端假装后台已授角色级权限。
- 产品发布/暂停、成员限制：显示正确对象和原/新状态，保留用户录入的理由；请求在途时阻止重复提交，失败仍可理解并继续任务。

**准出**：每项关键操作“成功 + 拒绝/冲突 + 断网/未知（适用时）”至少各1次真实受保护 API + Chrome 验证，撤权/阻断以后旧页面不继续显示可操作成功。**当前：NOT STARTED**。

### UI-G3｜权益、发码、审计正确性（P0/P1）

- Grant 创建/撤销：时段与 UTC/本地显示一致性，幂等 request ID；校验 429、503、响应丢失和刷新后核查，不因未知结果重放造成二次授予。
- 发码：明文单次展示、成功提示、复制/下载、离开安全确认、异常和关闭行为；清理易失内存与非秘密元数据，持续执行产物秘密扫描。
- 列表/用户/审计间深链的上下文保持；准确统计和时间展示，不能以“暂无数据”遮蔽 403/503。

**准出**：以安全隔离数据完成真实浏览器业务路径；明文只存在约定当次内存/下载响应，不出现在 URL、Query cache、持久化、日志；未知写入状态可核查。**当前：NOT STARTED**。

### UI-G4｜反馈闭环与敏感附件、导出（P1）

- 四个队列、详情、标签/星标/优先级/负责人/备注/公开回复，验证交叉编辑后的草稿保留、并发版本 409、恢复与历史。
- 私有附件在无图/1图/2图、错误权限、过期链接、损坏图片、超时等情况下有明确占位、重取或拒绝。
- ZIP 过滤、选中、20条限制和二次敏感确认；测试文件下载中断、失败和重新尝试、Blob 释放；导出内容需与服务器授权范围一致。
- 第一阶段使用已批准隔离测试存储/Mock 验证可独立完成的 Admin UI；**真实线上 R2 跨服务留第三阶段**，不得以模拟测试充当云上 PASS。

**准出**：端到端 Chrome 流程及附件/导出负例通过，敏感资料默认不选、取消后不留存选项，缺图时不生成貌似完整的 ZIP。**当前：NOT STARTED**。

### UI-G5｜统一业务状态与异常恢复（P1）

建立并逐模块落地以下最小状态合同（复用 MUI/RA；没有现实需求不开发“通用状态机框架”）：

| 状态 | 用户可见行为 | 不允许的结果 |
| --- | --- | --- |
| 首次等待 | 固定结构先出现，动态表体/值局部反馈 | 长白屏、全页跳变、无障碍静默 |
| 空数据 | 明确说明无记录 vs 等待查询条件 | 请求失败时假装空数据 |
| 后台刷新 | 保留仍有效的旧数据显示更新标志 | 旧产品内容误套入新产品、无限 spinner |
| 401/403、MFA | 及时阻断受保护操作，提示登录/再认证/权限失效 | 自动回退为普通空列表或持续可点击危险操作 |
| 409 并发冲突 | 提示最新状态，安全刷新与人工重试 | 偷偷覆盖、覆盖未提交输入 |
| 429/503/断网 | 显示可操作重试或稍后处理 | 假报成功、把网络错误解释为封禁 |
| UNKNOWN 写入 | 使用原请求号只读核验、谨慎恢复 | 立即生成新的高风险请求 |
| 成功反馈 | 对象、范围、结果可核对；相关列表刷新 | 成功 Toast 但目标数据未更新且无说明 |

**准出**：关键模块至少覆盖 8 类中适用状态的可重放自动化与重点人工验证；所有失败场景中无敏感数据泄露与错误成功状态。**当前：NOT STARTED**。

### UI-G6｜八维视觉、响应式、无障碍（P1）

**视觉**：统一真实工作任务截图，包括空/满/长文本、加载、错误、详情、高风险弹窗；逐页核对八维标准及中英文/数字/时间标注，形成修改前/后对比。不得用多余副标题掩盖视觉层级不足。

**响应式**：视口基线 320、390、768、900、1440px，加宽屏和动态高度；覆盖桌面表格/手机卡片、Modal 全屏、产品范围切换、键盘展开时移动端布局；200%/400%缩放无必要二维滚动。

**WCAG 2.2 AA**：在适用范围内通过 axe + 完整键盘 Tab/Shift+Tab/Enter/Space/Esc + NVDA/VoiceOver 人工测试；重点包括表格排序/列表分页、对话框 trap/focus return、动态错误宣布、无障碍名称、中文 IME、减弱动效、目标大小和文本对比。对 axe incomplete 做人工结论，不按 0 violations 自动签收。

**准出**：八维逐页截图通过、完整交互键盘/读屏清单 PASS、全站适用 WCAG 2.2 AA 无开放阻断项，**项目所有者签署视觉与交互确认**。**当前：NOT STARTED**。

### UI-G7｜最终 UI 性能与交付门禁（P1）

- 复用 [性能 S1–S6](./admin-performance-phase2-real-load-and-interaction-plan-2026-10-26.md)，真实测生产构建入口、导航、非空行首可交互、连续输入/筛选、图片/ZIP和长会话，不重复另一套指标文档。
- 按相同条件做前后对照，区分 FCP/LCP/CLS/INP、网络字节、组件提交耗时、请求次数、服务器响应和真实业务可操作时间；使用可代表的隔离数据。
- 将命令式测试 + 页面/场景证据 + 缺陷关闭 + 回归门禁汇总为最终审核包，不把未获批准的部署端/真实网络环境写为已测。

**准出**：性能专项对应门禁 PASS、UI-G0～G6 全部对应子项关闭、无开放 P0/P1、所有者确认第一阶段；然后才依据三阶段总则推进第二阶段。**当前：NOT STARTED**。

## 5. 每页必须执行的共同验收清单

对 `3` 中每个页面/弹窗，都按下面的核验序列记录 PASS / FAIL / NOT RUN：

- [ ] **数据语义**：真实受保护 API 返回、字段含义准确、账号/产品/权益状态不混淆；关联数据丢失或 403 不假装正常。
- [ ] **正常任务**：进入、找到、搜索/筛选/排序/翻页、查看/操作、回退到来源，关键上下文正确。
- [ ] **边界任务**：0 / 1 / 20 / 21+ 行、多页、长文本、特殊字符、日期/时区、空引用及异步切换。
- [ ] **等待与刷新**：首屏结构立即可见、无长期空白、局部 busy/更新态与真实数据稳定。
- [ ] **权限与故障**：匿名、AAL1、AAL2、撤权、401/403/409/429/503、断网/超时，安全拒绝和准确提示。
- [ ] **安全操作**：确认范围/后果、阻止重复提交、失败保留输入、UNKNOWN 可核查、敏感状态离开前保护。
- [ ] **响应式**：320/390/768/900/1440、200%/400% 和适用的真机交互，重要控件不遮挡。
- [ ] **无障碍**：键盘、读屏、焦点、状态提示、表单错误和对比度；记录工具版本、incomplete 人工判定。
- [ ] **八维视觉**：层级/字体/留白/色彩/组件/微交互/响应式/无障碍；所有者有可复核截图与意见。
- [ ] **性能**：响应/交互预算和真实 SPA 数据作用域，不因性能调优降低权限或业务语义。
- [ ] **回归与留痕**：自动化命令、退出码、截图/视频/JSON 证据、异常日志、合成数据清理及评审人。

不适用（N/A）需注明理由；只存在代码却未测，必须标 `NOT RUN`，不得默认为 PASS。

## 6. 测试环境、数据与自动化执行策略

### 6.1 一致环境与分层证据

1. **静态/工程层**：`pnpm build`、`pnpm lint`、类型检查（已包含在构建时按脚本实际输出确认）、`node scripts/test-d3-phase1-foundation.mjs`、`git diff --check`。它们不能代替 UAT。
2. **隔离 Supabase + 真实受保护 API**：真实 AAL2 / RLS / 业务 RPC，合成可清理账号和数据。所有治理写仅作用于已批准 QA 身份/测试记录，不触碰真实管理员；记录撤销/恢复和清理。
3. **正式构建浏览器**：独立 Chrome profile、CDP/适用 E2E，视口/网络/CPU、截图、axe、交互完成时间；避免重用浏览器状态导致虚假缓存通过。
4. **人工验收**：键盘、NVDA/VoiceOver、视口缩放、真实用户任务、八维视觉和所有者签收。自动 0 违规只能作为一个证据。
5. **线上/跨端**：只在总则指定阶段与明确授权后进行；本计划不下达推送、真实 R2/SMTP、云端权限和生产数据操作授权。

### 6.2 场景素材最小集

- 测试身份：匿名、普通 AAL1、合格 AAL2 Admin、失效/blocked 或撤权的**一次性合成账号**；权限拒绝的测试需证明服务端拒绝。
- 多产品：draft/active/suspended，少于和超过100产品的选择器边界在安全隔离数据中构造。
- 用户/成员：无成员、active/left/suspended、平台 blocked、不存在/查找失败、跨产品多条历史。
- 权益/发码：即将到期、未来生效、永久、撤销、重复 request ID、429/503/UNKNOWN、已兑换码/首响应码。
- 反馈：四队列、长正文、中文标签、0/1/2图片、归档/软删/恢复、导出选中和过滤、安全失败。
- 规模：10/20/21/100/1000/10000 级别**按需要及安全预算使用**；不能把现有48行小样本当大规模验收；数据隔离、可清理、索引计划与真实容量另以性能专项为准。

### 6.3 每条证据的记录模板

`ID | 归属 UI-Gx | 页面/用户任务 | 代码版本/环境 | 测试身份/样本类型 | 视口/缩放/网络 | 期望 | 实际 | PASS/PARTIAL/FAIL/NOT RUN | 命令/退出码 | 截图/JSON/视频路径 | 问题编号 | 修复版本及重测 | 人工复核/所有者签收`

浏览器日志和截图需脱敏：不暴露 access/refresh token、TOTP secret、邮箱明细、私有原图、兑换码明文及真实用户身份。合成测试数据和临时账号严格记录创建与清理；清理失败则整个测试执行不得标总体 PASS。

## 7. 施工顺序、依赖与完成定义

| 批次 | 顺序 | 交付件 | 阶段准出 |
| --- | --- | --- | --- |

**跨专项依赖**：登录/TOTP 恢复对应 D2；产品/成员/发码/反馈 RPC 合同对应 D1/FB；登录网络和数据大规模指标对应性能 S1–S6；平台管理员角色升级与账号删除不属于本 UI 文档直接授权。若需求发生变化，先修改权威领域文档再更新本矩阵。
