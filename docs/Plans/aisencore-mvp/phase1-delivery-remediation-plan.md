## P1｜Admin 前端性能、拆包与大数据成本（第一优先）

1. **P1-01 资源级懒加载**：把 Dashboard、产品列表/创建/详情、10 类通用列表、8 类通用详情、三类高危表单、用户 360、恢复页拆成路由级动态 import。为 Suspense 提供符合设计系统的加载态；不得在无 MFA 前预取受保护的业务数据。动态 chunk 必须可按路由独立生成。
2. **P1-02 依赖分包预算**：保留 Vite8/Rolldown 可缓存的依赖分组，逐步核实构建分块，禁止把所有业务静态引入统一 App chunk；建立文件体积与入口 gzip 基线对照。单 chunk 大小不是唯一验收。
3. **P1-03 请求去重**：Dashboard/product KPI 采用准确后端 count 并控制请求；产品选择器不能静默限制100条，超过界限应可查询/翻页，禁止不知情丢失选项。
4. **P1-04 规模性能**：使用隔离合成数据测 100/1,000/10,000 项、慢网和频繁切换；记录 LCP/INP/CLS、冷/热访问、路由切换、筛选与内存增长、XHR 数。为实际环境确定预算并固化脚本。
5. **P1-05 工程清理**：减少重复依赖、无使用 starter CSS/图像、危险副作用；模块提取以可测性为依据，不把抽象变成过度设计。

## T1｜通用表格、筛选、分页、关联与数据真实性

1. **T1-01 排序**：每个允许排序的业务列使用 MUI TableSortLabel / aria-sort，有明确升降箭头和服务端白名单排序；不允许客户端只排序当前一页。涉及合成字段（如即时有效状态）只显示不可排序列并解释。
2. **T1-02 筛选/搜索**：按任务设计，不新增没有授权的模糊用户搜索；成员/产品/Grant/批次/码/核销/审计/事件/治理支持获批准的明确字段筛选；任何用户查找必须仅精确邮箱或白名单 UUID。
3. **T1-03 分页正确性**：切换产品范围、搜索、状态、排序应重置页1；URL/页面返回的状态按产品需求保留；筛选空≠全库空；服务端 total 与页码越界有显式恢复。
4. **T1-04 表格密度与关联**：移动端卡片保留重要操作、完整 ID 一键复制；超长字段截断要能读取原值；行到详情/关联用户、Grant、批次、安全码、核销、事件和审计形成闭环。
5. **T1-05 大数据一致性**：产品菜单/用户360不得将前100记录当作全集；超过分页截断必须有“查看更多”或服务端逐页查询；状态/到期按当前时间更新。
**退出**：[ ] 10 个列表可验证排序及筛选 [ ] 全范围和分页边界 PASS [ ] 相关 ID/身份不泄漏 [ ] 响应式密度 PASS。

## B1｜高优先级业务安全流程

1. **B1-01 Pro UNKNOWN**：提交前保留不含私密信息的完整参数与 request_id；未知结果先按原请求查询 `entitlement_grants` 且最小权限过滤，只能显示本管理员可访问状态；已有同编号则明确结算，不存在才允许同编号重试；网络失联时保持 UNKNOWN；不生成新编号盲重发。服务端唯一键及并发幂等须有证据。
2. **B1-02 已知拒绝 vs 未知结果**：400/401/403/409/422/429 等已知拒绝明确显示，不进入 UNKNOWN；5xx/超时/断网保留原业务请求。具体 HTTP 状态码从 `supabase.rpc` 响应传递。
3. **B1-03 账号治理目标核实**：只有已解析匹配的账号 UUID/邮箱才能提交高危命令；失败或空匹配禁止仅靠手动打勾绕过；操作/目标/原因更改均应撤销上次确认。
4. **B1-04 状态感知**：产品、成员、Grant、码、批次、管理员、封禁状态使用服务端真值控制操作；不适用操作隐藏或禁用并解释，409 冲突刷新正确状态。
5. **B1-05 恢复与时区**：永久/显式时间窗、空日期、非法时间和时区，发码数量边界、停用账号时权限结果与旧 JWT、MFA/账号恢复界面等都要完整验证。
**退出**：[ ] Pro UNKNOWN 503/超时/已有/未有 + 刷新 [ ] 身份不明确治理不可提交 [ ] 错误响应不重复高危写入 [ ] 证据留存。

## V1｜八维高标准原创视觉

- [ ] Typography：采用一致中文主字体/英文/数字字阶，去掉没有意义的过小辅助字；对比度与段落密度适配真实管理任务。
- [ ] Whitespace：统一间距阶梯，Dashboard 减少空泛装饰占比，密集运营列表不过度留白，关键卡片与详情节奏一致。
- [ ] Visual hierarchy：操作目标、风险和下一步明确；复杂流程优先高信号信息而非模板化英文眉题/说明文字。
- [ ] Color：收敛语义 Token（主/次、成功/危险/信息、焦点/禁用/渐变），禁止同语义多套局部 hex，状态多通道编码。
- [ ] Motion：加载/更新/确认/路由转场自然、不过度华丽，符合 reduced-motion。
- [ ] Micro-interaction：精准 Hover/Press/Focus/错误/成功/禁用/上传导出，变化要可预测、能恢复。
- [ ] Responsive：各种信息密度全断点拥有版式规范，复杂对象仍高可读。
- [ ] Originality：以现代获奖级审美为参考但忠于 SaaS Admin 的效率与可信度，不照搬旧 Demo 或盲目美化；同功能两套候选基准对比后由所有者选定方向。
