# AisenCore Admin 兑换码单页面重构开发计划（2026-10-29）

## 0. 已批准业务决定
- **每个兑换码最多成功核销一次**；管理员无可调节「每码核销次数」。后端发行 RPC、数据库 CHECK 与核销唯一约束须共同强制，不能只靠前端字段隐藏。
- Admin 左侧只有一个「兑换码」入口，路由 /code-batches，显示全部发行批次；点击一批进入 /code-batches/:id/show，在同页查看该批次全部码的状态及成功核销事实。取消独立 /codes、/redemptions 页面和三个 Tab。
- 新项目无需保留旧版多次核销 UI/路由兼容层，不建立历史数据迁移补丁；**不等于授权删除真实业务数据、审计或明文安全措施**。底层保留批次、兑换码、核销事实三张表作为正常关系模型。
- 全部以顶栏产品选择器为范围；仅全平台时显示产品信息。继续保持 AAL2 管理员安全、首次发行明文一次性可见、随机码 Hash-only 持久化、发行幂等与请求结果未知时的原请求恢复、撤销理由与审计、已兑现权益不受撤销影响。

## 1. 主要用户流程
1. 打开「兑换码」→ 批次列表。桌面固定标题/筛选/发行按钮及表头，只滚动数据行。支持分页、日期倒序与精确批次请求号查询，显示批次名称（可用备注作为短名称）、权益规格、发行总码数、已核销数、剩余可用码数、失效码数、发行时间。全局增加所属产品列。
2. 发行兑换码弹窗：选定产品、发行数量(1..1000)、Pro 天数(1..36500)、到期时间(可选)、备注(可选)；**不出现最大核销次数输入**；提交固定 1，收到成功明文后强制一次性确认保存才可关闭；仅保存非秘密请求元数据用于未知结果确认。
3. 点击批次→详情：摘要总数/已核销/可用/失效，单独表格逐码显示批次内序号、安全前缀、状态（可用/已核销/已过期/已撤销/产品不可用）、核销账号、核销时间，按状态筛选与分页。核销账号可跳转用户360°，授权可从单条进入权益授权详情；不显示明文、Hash。
4. 撤销：仍支持单码/整批由受保护管理命令执行；撤销前展示确切影响，不撤销已有 Pro。已使用码不应在业务上被“撤销后再可核销”。
5. 精确检索：批次主列表按请求编号查询，不应搜索明文码；支持自用户/授权详情深链到某批次时定位已核销条目，可在后续版本继续优化。

## 2. 数据契约与状态口径
- 单次核销：batch.max_redemptions_per_code=1，codes.max_redemptions=1，codes.redeemed_count in (0,1)，redemptions.code_id 唯一；服务端发行参数不为1直接 PT422，事务中行锁和唯一约束双保险。
- 可用：没有核销、没有撤销、未过期、且产品活跃。已核销优先级高于已撤销；计数按单码，不是授权记录数和核销次数总和（此处皆为1）。
- 可用码数、已核销数、失效码数相加必须等于批次内码数量。失效码包含撤销/过期/产品不可用未核销的码。批次状态按进度计算，不额外维护可能漂移的可变状态字段。
- 服务端只读 AAL2 聚合/分页命令保证跨产品范围、状态、有效期统一；不允许因查询错误把统计伪显示0。单产品请求另一产品批次应拒绝或返回无记录。
- 技术请求 UUID、完整内部 UUID 默认隐藏在二级详情/复制入口，不作为表格主列。
