# AisenCore Admin 三分区浅色悬浮工作台设计与施工计划（2026-10-25）

## 设计问题和目标

截图中顶栏深蓝黑与米色业务页面明显割裂，左侧侧栏和右侧内容处于同一个平坦背景层，当前页名称「产品目录」既出现在顶栏又出现在正文，顶栏「工作范围」与下拉选择重复，产品选择器又被推到了最右边。当前结构更像一块连续的灰色平面，而非生产级操作工作台。

**用户确定的改动**：彻底移除顶栏动态资源标题（`TitlePortal`，不影响浏览器 document title）以及可见「工作范围」标签；产品范围选择器紧贴左侧品牌并留出识别间距；将应用外壳分为顶栏、独立悬浮导航卡、右侧内容工作面板；统一明亮、有空气感、克制的轻质感和浅层透明度。仍保留唯一「工作区」菜单组的五个一级入口和平台管理四个二级视图。

## 设计规范（UI token / 视觉合同）

| 层级 | 意图与实现参数 |
|---|---|
| 画布 L0 | 极低饱和雾灰偏冷底 `#F3F5F8`，不使用大幅渐变、光斑或深色幕布；内容周围露出 14–20px 气口 |
| 顶栏 L2 | 64px 左品牌、左侧工作范围下拉、右侧刷新/账户；浅色近白 `rgba(255,255,255,.89)`，backdrop blur 14px，细边线、轻柔投影，不以深色粗色块抢视觉 |
| 侧栏 L1 | 900px以上显示独立圆角卡片，边界在画布上可见；`rgba(255,255,255,.94)` + 1px `#E5EAF0` + `0 10px 32px rgba(33,50,69,.055)`；选中项低饱和浅紫，入口44–46px，底部环境标记只出现一次 |
| 正文 L1 | 同独立白/暖白纸质面板，圆角 18–22px、细边与不张扬的阴影，独立承载表格/标题/工具栏；不反向修改业务页数据区和表单契约 |
| 文字 | 标题墨色 `#1D2936`、次级 `#5D6B77`，紫色仅用于选中、CTA；顶栏范围选项16px以内，账号不会与背景混色 |
| 交互 | 120–200ms hover/focus、按钮可见焦点环、范围弹层键盘可用；遵循 `prefers-reduced-motion` |
| 响应式 | ≥900px 双面板固定侧栏并随内容滚动；600–899px 抽屉导航 + 完整范围选择与账号；≤599px AC logo + 抽屉按钮 + 紧凑范围 + 账号，不能超过320px视口；模态抽屉仍作为独立可见卡片 |
| 性能安全 | 不引入外部字体/图片/设计框架，不改 RLS、RPC、身份策略、产品作用域，仅修改主题、外壳、面板布局与自动化截图断言 |

## 实施步骤和证据

1. W0：读取 `App.tsx`、`theme.ts` 与 React-admin 的实际 AppBar/Layout/Sidebar 结构；固定当前五入口 IA 与已通过 E2E 基线。
2. W1：顶栏去重复 TitlePortal 和工作范围标签；范围紧跟 Logo、与右侧系统动作彻底分开。统一 Select 菜单交互与主题色。
3. W2：主题引入浅色表面系统；React-admin 顶部、侧栏、内容容器形成三层独立圆角布局，靠明确背景/边框/柔和阴影而非重度毛玻璃装饰。
4. W3：320/390/768/1000/1440 等断点调整间距与隐藏逻辑。保留移动抽屉触控与所有原业务导航深链。
5. W4：更新浏览器布局自动断言：顶栏不显示资源名/「工作范围」字样；产品范围在品牌右邻，桌面右操作与左组分离；三个分区具备各自背景、圆角和实际留白；320px不整页溢出。
6. W5：运行 `pnpm build`、`pnpm lint`、源码边界/构建密钥扫描、`git diff --check` 与真实 AAL2 Chrome 业务回归（包括敏感操作和 QA 清理）。
7. W6：记录测量截图及无法覆盖的项，同步 TODO 和第一阶段文档；对 NVDA/VoiceOver、200/400% 浏览器缩放、真机与所有者八维签收保持 OPEN。

## 不可牺牲项

不得删除右侧内容正文「产品目录」的真正 H1，用户要求删除的是**顶栏重复**四字。保留全局产品选择器及其 aria-label，不能隐藏作用域意义；保留真实权限校验、用户查找限制、危险操作、UNKNOWN 不得盲目重复和一次性兑换码明文保护。不重建 React-admin 布局系统，不推送、提交、部署或清库。
