## 1. 问题、目标与不可变更边界

当前侧边栏把 12 个导航入口平铺成三个技术性类别，其中六个是同一业务链条的流水/权限视图、两个是重叠的用户与成员查找。目标是让管理员按业务任务定位而不是按表名寻找，同时保持所有受控安全查询、历史审计、原 Resource URI、MFA 和高危写入 RPC 完全不变。

**禁止**：移除已实现业务能力；改变 Resource 或后端 API/RLS/RPC/权限；让 `users` 变为可枚举全部账号；混淆全平台封禁和产品成员暂停；额外创建套餐/计费/统计/设置模块；新建第二套菜单框架、路由状态管理或数据缓存；推送、部署、清库。

## 2. 最终导航及页面映射

一级固定为六个：`概览` `产品` `用户与成员` `Pro 权益` `兑换码` `平台治理`。

| 一级导航 | 路由入口 | 同一模块二级视图（上下文内可达） | 其他相关页面 |
| --- | --- | --- | --- |
| 概览 | `/` | 无 | 数据卡链接到原业务资源 |
| 产品 | `/products` | 无 | `/products/create`、产品详情、带产品上下文的成员/Pro/码路径 |
| 用户与成员 | `/memberships` | `成员关系 /memberships`、`查找账号 /users` | `/users/:id/show` User360、`/memberships/:id/show`、`/membership-events` 历史归档（保留深链，不作为永久侧栏入口） |
| Pro 权益 | `/grants` | 无 | `/grants/:id/show`、`/grant-new` |
| 兑换码 | `/code-batches` | `发行批次 /code-batches`、`兑换码记录 /codes`、`核销记录 /redemptions` | `/issue-codes`、批次/码详情 |
| 平台治理 | `/audit-logs` | `管理审计 /audit-logs`、`账号限制 /restrictions`、`管理员权限 /admins` | 审计/限制/管理员详情、`/account-actions` |

**二级呈现**：侧边栏固定只展示六个主业务入口；有并列视图的模块在工作区页首展示同领域导航（MUI 官方 Link/Tabs，路径作为唯一选中真源）。组件须有明确导航标签、可达焦点、键盘导航与移动可滚动/不横溢的布局。直达旧深链仍能找到所在领域；返回不强迫跳到无关业务表。实体详情使用语义面包屑或具名返回路径，避免裸数据库 UUID。

**作用域**：成员关系/Pro/批次/码/核销可按顶部已选产品过滤；账号精确查找、管理员、账号限制、审计和全平台成员事件历史不随产品变化；在对应页面明确显示全平台。链接携带实体产品上下文时采用既有受限查询或显式选择产品的方式，不把前端筛选当作授权依据。

## 3. 分步任务与质量门槛

- **P0 设计锁定和基线**：读取当前 `App.tsx`、WorkspaceLists/Details、UserShow、现行设计合同、已有 E2E；保持已有 dirty worktree；预先记录路径及历史功能清单。
- **P1 侧栏重组**：删除 12 个平铺菜单入口呈现，仅保留六个领域目的地；有意义的图标、可见活动状态、移动抽屉兼容，路由本身不删除。
- **P2 领域内二级导航**：实现轻量复用模块导航，仅在其资源列表显示。固定项选中从 pathname 派生而非新增 Store；命名不暴露数据库结构。
- **P3 详情与历史通达**：用户 360/成员详情提供成员事件及必要治理操作上下文；产品详情提供跨模块导航并带正确产品作用域；保留首次发码明文只展示一次及其他敏感操作路径；成员事件和原账号管理路由可深链访问。
- **P4 自动化**：`pnpm typecheck`、`pnpm lint`、`pnpm build`、源码边界与 Chrome 本地 AAL2 业务回归；增加一级菜单数量/入口/二级切换/URL 刷新选择/键盘/390px和320px检查，保证高危 RPC/QA 清理仍过。
- **P5 文档及复核**：更新现行导航架构、TODO、施工记录，标记代码完成和实测范围；未测真机/读屏/200%和400%缩放/所有者签收不写成 PASS。
