# AisenCore Admin 反馈中心精简与批量治理修复计划（2026-10-29）

> 所有者新要求，适用本地第二阶段开发。工作树已有未提交变更，禁止覆盖、清库、未经批准推送/部署。仅将真实执行且有证据的任务标为完成。

## 目标和已决定的唯一交互合同

- 反馈继续保持三种有效队列：**收件箱 → 处理工作台 → 已归档**，归档可重新进入工作台。不再提供回收站或软删除/恢复 UI；不要把「删除」伪装成移到回收站。
- 管理员可从当前页勾选多条反馈，**批量移动**（合法队列转换）或**批量永久删除**。单项与批量共用一套服务端授权、版本与审计合同。按允许的来源队列提供动作，跨队列不自动偷偷迁移；UI 不显示服务端不支持的动作。批量处理必须显示选中项、对象数量、目标队列、进度/逐条成功与失败，以及部分完成结果，变更选择/产品时禁止旧确认生效。
- **永久删除意味着同时移除**数据库反馈正文、私有备注/事件、附件元数据、R2 原图及派生缩略图。只有服务端完成真实清理和事实核对后才返回已彻底删除。R2 与 PostgreSQL 无跨服务原子事务：应使用短小、持久、可重试的管理员受保护清理任务，先冻结目标、删除对象、后删除 DB 记录，失败不报告完成且必须可继续；不得直接在浏览器使用 R2 凭据/删除数据库表，禁止批量清理其他用户或目标。保留最小无内容/图片/联系信息的管理审计；实现时逐一确认外键、RLS、私有图片 key、竞争写入与幂等恢复。必须测试 0/1/2 图、404、503、失联、部分完成、并发更新、撤权、重复提交和清理重新进入。
- 取消所有**管理员自定义标签**的筛选与编辑；现有五个用户提交的反馈类别 `bug/account/experience/suggestion/other` 对应「问题反馈/账号问题/体验问题/功能建议/其他」是唯一类别筛选选项，并在每条反馈列表中清楚显示。无需添加第二种标签体系。旧 tags 字段与后端 RPC/ZIP 路径要同步收敛，避免界面与真实筛选不一致。
- 产品通过**最上方产品选择器**决定范围：单产品视角不重复显示所属产品；全平台视角才在列表行、详情头部展示实际产品，不把客户端选择器当做后端授权。
- 界面坚持少文案、少重复按钮；保留当前三队列、优先级、星标、内部备注、来源用户、历史、含图预览、受限 ZIP 及权限控制的必要能力，不引入客服 SaaS、五态/人工回复/派单。

## 2026-10-29 筛选下拉运行时崩溃（用户截图）

- **根因已真实复现**：MUI 三种 Select 选择选项后更新 URL 查询参数，React-admin 依赖的 `query-string@7.1.3` 解析时调用 `decode-uri-component`；工作区 `pnpm-workspace.yaml` 为修复旧解码器拒绝服务问题将后者统一覆盖为 `0.5.0`，其 CommonJS `require()` 返回 `{default: function}` 而不是函数。原版 `query-string` 直接调用模块对象，抛出 `TypeError: decodeComponent is not a function`，导致错误边界接管页面。**不是表格、下拉选项或反馈数据异常**。
- **修复方式**：保留安全覆盖 `decode-uri-component: 0.5.0`；新增 pnpm 对 `query-string@7.1.3` 的最小兼容补丁，支持函数导出及 `default` 导出，修改 `pnpm-workspace.yaml` 和 `pnpm-lock.yaml` 保证所有重装可重现。无需改动三个筛选逻辑，也不牺牲 URL 筛选上下文。
- **本次验证已通过**：使用真实 React-admin 已安装依赖解析路径执行 `query-string.parse('priority=high&star=true&category=bug')` 和 stringify，原来的 `decodeComponent is not a function` 不再出现；Node 静态合同脚本已加入相同路径的实际运行时解析断言并 PASS。`pnpm install --offline --frozen-lockfile --ignore-scripts` PASS，Admin TypeScript/Vite Build PASS、Lint 0 错误/0 警告、`git diff --check` PASS。
- **仍待浏览器签收**：尚未在已认证 Chrome 中逐个点击优先级/星标/反馈类别三种下拉并保存真实截图，因此不能声称浏览器交互已完整通过。由于修改依赖实现，开发服务必须重启，并视需要使用 Vite `--force` 以清除旧预构建缓存，之后再验收。

## 当前需特别核对的风险

1. 原表 `feedback_attachments`、`feedback_events` 对反馈 ID 使用 `ON DELETE RESTRICT`；不能直接 DELETE 父表而省略受保护子表删除。
2. R2 原图和 `<key>.thumb.jpg` 是两个对象；对象删除与数据库提交不具 ACID。失败后应明确保留待清理事实，不丢掉可恢复的对象 key。
3. 旧回收站可能有本地真实业务行；移除入口前先只读盘点，禁止静默抹去数据。
4. 单产品选择器是视图过滤而非服务端授权，所有批量写都须校验每条真实产品与确认的范围。
5. 废弃的历史自定义 tags 和 V2 RPC/测试不得继续驱动新 UI；新的类别选择应采用服务端已存的 `category` 枚举。
6. 任何云端 R2、生产迁移、Git 推送部署均不在当前许可内。
