## A01｜Auth、MFA、会话与账号生命周期（P1-03）

| 编号 | 最少覆盖范围 | 必须留下的证据与判据 |
| --- | --- | --- |
| AU-01 | 真实注册、确认邮箱、旧/错误/已使用/超时链接、密码找回 | GoTrue/Mailpit 真邮件+受保护回调、稳定 Auth user_id、旧密码失效；不得仅靠模拟链接 |
| AU-02 | 正常 session 与 `PASSWORD_RECOVERY` 区分，直接无凭据改密拒绝 | 浏览器端状态及受保护 HTTP 正反例；401/403/422/503 明确 |
| AU-03 | TOTP AAL1→AAL2、匿名及普通用户操作管理接口 | 真 token/签名/服务端资格复核；拒绝不依赖按钮隐藏 |
| AU-04 | 被撤管/blocked 的旧 access token、两个独立会话、refresh/local-global logout | 旧会话权限与响应在权限变更后可复测，未泄露其他会话 |
| AU-05 | A-04 管理员丢失主 TOTP 因子/备用因子恢复演练 | 隔离管理员、备用验证器、旧因素撤销、AAL2 恢复、旧会话实际观察及审计；不得公开恢复秘密 |
| AU-06 | 401/403/429/503/断网/超时、迟到响应 | 失败不误报“封禁”或“操作成功”，未知完成状态可查询，UI 不沿用旧用户身份 |
| AU-07 | 账号人工注销/保留策略（首发前决定） | 渠道/责任人/合法保留与匿名化的决定记录；仅受控演练，当前不执行正式删除 |

**顺序**：先复用 `scripts/test-d2-auth-api-mfa.mjs` 和现有 Lens 真实浏览器脚本核实历史结果，再补漏测用例；所有带写操作在隔离账号执行，A-04 需确保备用恢复能力，避免真正锁死唯一管理员。

## A02｜数据库与业务 RPC 安全/并发/规模（P1-04）

1. 在现行代码和迁移上列出适用的 `I-01～28`、`R-01～16`、`REV-*` 与近期权益信用/单码单次/用户目录/后台三卡/反馈 V4 增量场景；不盲目运行已被唯一新合同废弃的旧断言。
2. 数据层：RLS 正反例、函数 EXECUTE/owner/search_path、AAL1 拒绝、产品 ID 失配、用户封禁/成员暂停与权限撤销、敏感错误不枚举。
3. 真实网络层：GoTrue/JWT/HTTP，覆盖 401/403/409/429/503、同号重放、失败后核对、避免二次发码/重复核销/重复 Pro。
4. 并发：`LCK-01～08` 基础上增加真实多用户/跨产品/永久 Pro 与单码抢兑/管理员撤权交错；记录是否有锁等待、超时或死锁，不能只用模型断言。
5. 规模：`admin_list_users`/`admin_lookup_users`、反馈/授权/发码 count+分页、权益摘要 100/1000/10000 级真实代表数据 HTTP P50/P95 和 `EXPLAIN (ANALYZE, BUFFERS)`；真实运行环境、并发数与样本数不可省略。
6. 灾备：保留 QA 基线与授权范围，演练 pg_dump→隔离恢复和迁移前向修复；禁止以“可回滚代码”代替数据库数据恢复策略。

**验收**：每组存在实际运行日志、前后数据基线与用例结果；性能阈值未确定的先冻结候选标准并由责任人决定，不把历史开发机数字冒充生产 SLA。

## A03｜Admin 全资源功能、无障碍和性能（P1-05）

**功能路径**：真实注册用户列表/用户 360、成员/暂停恢复、账号封禁与管理员资格独立入口、Pro 授予/撤销/永久/到期、兑换单页批次/码/核销、反馈 V4 三队列及批量删除、管理审计和概览统计。对每类页面覆盖非空/空/过滤/分页、顶层产品选择、跨产品切换、移动端、长内容、真正的危险写入确认/审计及未知结果恢复。

**分层测试**：
- 自动静态：`scripts/test-admin-dashboard-metrics.mjs`、`test-redemption-single-page.mjs`、`test-admin-governance-separation.mjs`、`test-feedback-v4-contract.mjs`、现有 UI/权限相关脚本；
- 真 Chrome AAL2：用户导航实际点击、关键表格与弹窗、旧登录在途竞态、反馈三种筛选下拉、批量选中确认失效、永久删除待清理恢复、桌面/移动断点。
- 安全/故障：401/403/409/429/503、无网、响应丢失、读/写区别、产品范围漂移、权限撤回、所有者数据不被 QA 修改。
- WCAG 2.2 AA：自动 axe 结果和 `incomplete` 人工处理分开；NVDA/VoiceOver、Tab/焦点顺序、Escape、IME、200/400% 缩放、320/390/768/1024/1440px 与主要错误态；人工视觉最终由所有者决定。
- 性能：浏览器实际网络瀑布、登录 LCP/INP/长任务、路由首反馈、列表 count/分页、查询取消、含图预览/ZIP、多用户与慢网；此前记录 LCP 中位约 2936ms 高于候选 2500ms，须复测后才可改变结论。

**验收**：按页面/测试场景列 `PASS / FAIL / NOT RUN / WAIVED`；“构建成功/源代码 PASS/74 组自动截图”不代替人工读屏与设计签收。

## A04｜Core×Lens 第二阶段真正组合验收（P1-06）

**入场条件**：E02/E03 当前反馈合同稳定、相关 Auth/DB 门禁可用，QA 数据隔离并能回收。采用 Lens 正式 WebApp 真实操作产生的 user_id、product_id、membership_id、grant_id、feedback_id 等关联证据。

**主路径及异常**：
1. Lens 真登录→成员自动/显式加入→当前 Pro 权益→同产品合法兑换→Lens 资格展示与到期/撤销 Free 回归。
2. 同一用户 Lens 兑换→提交 0/1/2 图（含已确认邮箱与联系邮箱）→Core Edge/DB/私有对象→Admin AAL2 处理/ZIP →Lens 再查询→撤权/切号/失联。
3. 其他产品兑换码不可跨产品使用；重复码/请求 ID、HTTP 409/429/503、未知结果原号恢复、左退/恢复、suspended/blocked 与旧 JWT 均有服务端拒绝证据。
4. 已加载本地 Free 离线与恢复、不丢 IndexedDB 项目/加密材料、跨标签/会话切换时旧响应失效；真正物理设备/长时间过期/冷启动离线是否属于首发范围由所有者签名确认。
5. 确认 `LENS-06` 完整分析模板私有云备份的发布范围：若仍 DEFERRED，则本次本地综合验收及公开文案**不得声称备份 MVP 已交付**；若要求纳入，则需要单独的 S1 原子配额/白名单/20 份/5MiB/恢复/对象/失败对账及第三阶段真 R2 门禁，不能简单豁免。

**完成**：一张按真实入口贯穿的 ID 关联证据表、时间/版本/退出码、异常恢复/清理记录，及所有者对 Stage2 主路径和排除范围的书面决定；个别历史子链 PASS 不自动等于整个阶段通过。

## A05｜第三阶段环境检查与云测试（P1-07，必须授权后执行）

**批准门槛**：W8 本地报告 + Owner 的**测试环境部署授权**（具体目标/范围/执行者）；允许 Git 推送或创建远程资源须单独符合已批准范围。真实操作前只读核对目标环境以防误连生产。
