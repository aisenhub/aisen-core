## 1. 每次检查的必要字段

| 字段 | 填写约定 |
| --- | --- |
| 检查 ID 与责任人 | 例如 `E01-FROZEN`、`E02-LEGACY-RPC`、`VD-05`、`AU-05`、`STAGE2-CL07`，实名责任需由项目所有者指定，不预填 |
| 代码版本/工作区 | 精确 Git commit、branch、`git status`、依赖锁/patch 版本；若未提交变更标记其真实内容 |
| 环境/数据 | `SOURCE` / `SQL ROLE` / `JWT HTTP` / `AAL2 CHROME` / `LOCAL S3` / `REAL R2` / `CLOUD STAGING`；隔离产品/用户，生产数据禁入 |
| 数据库/服务版本 | Supabase CLI、本地/远端**准确目标**、迁移版本、GoTrue、Edge、Chrome、Node/pnpm/Deno |
| 用例和原始观测 | 命令/步骤、测试数据 ID（脱敏）、响应码/错误码、逐项断言、对象/SQL/审计基线与操作结果 |
| 真实结果 | `PASS`、`FAIL`、`BLOCKED`、`NOT RUN` 或 `WAIVED`；禁止用“代码已实现”表示 `PASS` |
| 执行与复核 | 日期时间、exit code、日志/截图/trace/查询计划位置、失败复测、QA 精准清理结果、复核者 |
| 例外/风险决策 | 豁免理由、影响范围、负责人、风险承接与到期条件；没有所有者决定不可把 `NOT RUN` 改为 `WAIVED` |

## 5. 事故或失败的验收处理

对不可逆操作（反馈永久删除/账号注销/对象/数据库清理）一旦出现错误目标、不明结果、权限不正确或 QA 清理失败，立即停止继续写入，保存脱敏日志与现场清单，先只读确认完成状态/对象引用/历史数据，再按已有恢复计划操作。未经验证的修复不能直接改为 PASS。
