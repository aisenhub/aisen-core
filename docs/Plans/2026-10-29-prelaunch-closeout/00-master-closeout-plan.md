## 3. 工作包操作规则

### W0：冻结基线与数据安全

1. 记录 `git status --porcelain`、当前 branch/HEAD、未跟踪/忽略的唯一证据、实际 Node/pnpm/Deno/Supabase/PostgreSQL/Chrome 版本、现有迁移列表。
2. 明确 QA 的**隔离** Auth、数据库、对象存储、AAL2 管理员和 Lens 指向；不复用用户真实业务数据做永久删除测试。必要时仅获授权后做仓库外数据库备份，并确认恢复可行。
3. 测试建立前后基线：Auth/产品/成员/Grant/反馈/附件/审计 ID 集、R2/S3 对象键数与允许变化的 QA ID；所有测试必须精确清理新建身份/对象。
4. 将 2026-10-29 审查观察与本轮新执行分栏。遇到已有数据不清楚、外部响应结果未知或共享数据库正在被写入，**停止写入，先只读取证**。

### W1–W3：编码安全门禁

- 每个缺陷先新增失败检查（锁安装/真实 JWT 旧 RPC/删除故障），然后实施最小修复；不得为旧行为保留兼容 API。
- 对已应用 SQL 只能创建合法后续迁移；不改旧迁移或重置生产数据。核对 GRANT/RLS/owner/search_path、同事务审计和故障后恢复。
- V4 删除涉及不可逆数据，必须在受控测试身份和本机隔离对象存储证明安全；没有真实云 R2 授权时只能标 `LOCAL S3 PASS / REAL R2 NOT RUN`。
- 每个子项完成后立即同步当前 spec/architecture/开发规范、TODO 和计划验证记录，记录所有未覆盖范围。

### W4–W7：业务/体验与文档收口

- 测试优先复用现有 `scripts/test-*`、pgTAP 和真实 Chrome 夹具，避免额外通用测试框架；统一入口可用最小 npm/pnpm 脚本或清单实现，不必造新测试平台。
- 局部源码断言、SQL 模拟角色、真实签名 JWT、AAL2 Chrome、本地 S3、真实 R2、真实部署分别保留证据标签。
- 候选阈值与已确认阈值区别记录；此前匿名慢网 LCP 中位约 2936ms，对照候选 2500ms，未复测不得宣称解决。
- 完成过程计划需把仍有效的安全不变量、测试和 OPEN 转到权威处，再退出活动索引；不得删除唯一截图、未跟踪证据或有效旧迁移。

## 4. 停止/阻塞条件及升级

出现以下任一情况应停止相应**写入型**测试、保留现场：冻结安装仍改动 lock、旧 RPC 权限无法确认、AAL1 可进行管理员危险写、实际影响非 QA 用户/对象、永久删除返回成功但 DB/对象仍留存、未授权云连接或账号/产品错指、不能复原 QA 数据、测试结果未知被标记 PASS。记录 `FAIL/BLOCKED`、输入、请求 ID、环境、状态码、原始日志（去密）、数据基线、恢复步骤、责任人。

## 5. 进入第三阶段测试环境的退出定义

- W1/W2/W3 的安全与构建阻塞项**全部有新的真实通过证据**；其他 P0/P1 均 PASS、明确延期出首发范围，或有**所有者书面豁免 + 风险承接人/期限**。不允许“未测”自动转为豁免。
- 核心授权、数据库、AAL2 失败与恢复、Admin、Core×Lens 实际主路径有可重放证据；本地数据和对象清理完成。
- 文档链接为 0 错误；根 README、spec、architecture、当前 TODO、计划索引不冲突；待清退文件的处理状态明确。
- 云端参数/密钥/域名/SMTP/R2/恢复/负责人就绪且申请写清**仅测试环境**目标和执行范围，项目所有者单独批准后方能执行。
- 第三阶段云端测试的 PASS 和正式公开上线的批准应当**分别**另行记录。
