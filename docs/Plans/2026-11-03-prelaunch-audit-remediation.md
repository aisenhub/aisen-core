# 上线前复核问题逐项整改计划

> 基线：`f4f0ec3`、本地 41 项迁移。依据[复核报告](../reviews/2026-11-02-aisencore-prelaunch-security-performance-audit.md)，所有者已授权制定计划并实施本地修复。云配置、推送、部署、清库不在授权范围。
> 本计划属于[MVP 总计划](./aisencore-mvp/00-mvp-master-plan.md)下的专项；开放事项统一在[TODO](./TODO.md)，这里记录步骤与证据，不构成第二套业务合同。

## 1. 执行纪律与数据保护

- 每项按权威文档 → 失败测试 → 最小实现 → 定向/相关回归 → 清理/证据执行；不将代码完成等同于真实 JWT、云端或人工验收。
- 仅连接已核对容器/端口的 AisenCore 本地服务。SQL 夹具事务回滚；HTTP 夹具仅清理自身新建数据并核对原数据保全。禁止 reset、seed、修改真实序列值或删除现有业务数据。
- SQL 结构/权限变更用现有 Supabase CLI 创建新版本文件，不改已安装历史文件、不做历史数据转换；安装前检查迁移内容及本地目标，安装后验证当前权限和调用链。
- 不引入依赖、额外服务、通用并发/限流框架；不为未证实的性能或配置问题预建方案。

## 3. 文件与调用链范围

- **SQL**：`supabase/migrations/` 新版本；新增数据库负向断言，必要时增加统计行为夹具；同步现有回滚脚本的用例数量。
- **Edge**：`feedback-submit/service.ts`、既有图片验证模块和相关 Deno 测试；核对入口、RPC 返回类型及 Lens 错误/恢复调用者。复用已有验证与存储实现。
- **Admin**：核对 `ProductCreate.tsx`、DataProvider、`GrantCreate.tsx`，不新增界面文案或无需要的返回字段。
- **文档**：数据库权限/锁序、API、反馈领域；复核报告写清修复前后事实；README、计划索引和 TODO 同步本地实际结果，不改人工/云门禁。

## 4. 验证顺序

1. 新增 SQL/Edge 行为测试，分别记录修复前失败；涉及目录声明的测试只检查真实安全/只读合同。
2. 用 CLI 生成并检查 SQL 变更，先在事务中演练新 SQL 与测试，确认后仅安装到本地；不在云端运行。
3. 跑完整本地事务回滚 SQL 套件、Deno 套件；核对最终 ACL、函数定义、schema 权限与管理员/真实用户数据保全。
4. 运行受影响的真实 JWT/HTTP/隔离私有 S3 与 ZIP 测试；性能测量保留样本和计划，不能冒充生产 SLA。
5. 对 Admin 调用链运行必要的类型、Lint、构建及现有行为检查；检查文档链接、失效描述、未使用代码和 `git diff --check`。
