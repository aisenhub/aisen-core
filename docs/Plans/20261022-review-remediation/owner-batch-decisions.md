## 二、六项决定批准后仍必须冻结的实施细节（技术实现负责，不再让用户替工程师拍板）

- **DEC-01**：当前唯一 RPC 签名 `redeem_code(product_key,code)` 的参数、错误优先级、left/suspended 与失败次数精确定义、当前调用方同步更新；旧签名不公开/不保留兼容入口；REV-B01 及侧信道负向测试。
- **DEC-02**：已选 Edge 小 JSON 路线，须测最小角色与凭据、R2 **final 条件创建**的实际 SDK 支持、对象 key、SHA-256、过期 quota 逻辑释放与物理清理、故障对账、审计和版本清理执行者；Worker/CopyObject 旧路线非首发条件。
- **DEC-03 最新前端清理**：G0B 工程历史删除事实保留；目前只要求使用[按风险的原型/AI 工作流](../../development/frontend/interaction-benchmark-workflow.md)和 React-admin/MUI 通用规范，不再强制单文件全景、四主题/固定布局或 DOM 1:1。历史 UI-G0A 尚未签收，不自动释放正式施工。
- **DEC-04（2026-10-23 复议及后续用户再次确认）**：不再创建 Free 版本与切换指针；每产品单份线上默认配置、审计、安全空值与全体用户下次可信在线计算。**Free 不能被兑换或直授**；首期兑换码和人工直授只创建**当前平台 Pro Grant**，绝不修改用户等级字段。最后一份有效 Pro 到期或撤销，自然只剩当前 Free 默认能力；多份仍有效 Pro 保留权益。历史授权不删、成员/账号/产品在线准入独立，本地匿名 Free 不依赖在线。
- **DEC-05**：缺省/NULL/永久/UTC 微秒/首次 computed ends_at 的规范化、actor 请求命名空间、同键异参冲突、合法 select=* 的安全投影。
- **DEC-06**：Auth Admin 的实际 PostgreSQL 读取能力与 GRANT/RLS/owner、批量 UUID 数上限和分页策略、失败降级、真实网络请求数和 P50/P95；失败则回退 Edge，不能为了 1 次 RPC 打开 auth.users 的 Data API。
