## 决定

记录当前问题、采用的最小方案、必要契约变化与尚待确认的决定。用户需求维护在 spec，体验选择维护在设计，已实现事实进入架构，尚未实施的技术施工方案留在此计划；相互链接，不重复抄写。

**仅当本任务实际制作了交互基准时**，在本节补充简短的「场景/原型路径和 Git 版本、已认可行为、未解决问题、交互认可/视觉认可/正式施工授权（分别标明）」；不复制规范或增设审批表。引导与原型本体遵循[产物规范](../development/frontend/interaction-benchmark-spec.md)。

## 步骤
