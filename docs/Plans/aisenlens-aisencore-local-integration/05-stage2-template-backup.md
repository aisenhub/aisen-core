## 4. 状态、事务与恢复

| 流程 | 可复测行为 |
| --- | --- |
| create | 字节/白名单/hash合法后，可信事务查身份/准入/Pro/owner/同号/份数，创建有界pending |
| 对象写 | 服务端唯一final key，If-None-Match:*条件创建；不覆写ready，不下发长期写凭据 |
| finalize | pending→ready时，同号/参数一致，锁内再查当前Pro/准入/owner及有效预留；对象事实匹配才ready；已ready的同号请求按读取权限返回原结果，不重复提交或扣份数 |
| pending过期/确定失败 | 逻辑释放预留，物理孤儿另按当前引用/保护期清理；超时不直接判失败或删除对象 |
| ready丢首响 | 原号/原参数查真实状态，只返回原安全摘要，不重建对象/占份数；异参409 |
| list/download | 只给本人ready元数据；下载每次实时授权，短URL不持久记录，本地缓存不作为云权限 |
| delete | 最小deleting→deleted幂等流程；**deleting仍计份数，物理删除且DB确认deleted后才释放**；失败可恢复，不假报完成 |
| 删除单侧成功 | 对象已删/DB确认失败时原操作重试确认；DB仅deleting不等于对象已删，未知先查状态，不换号造另一删除 |
| 孤儿回收 | 定界key/原号、保护期/当前引用、受限执行者及失败审计；已有引用或未知状态不删 |

原号各状态的重放、到期后查询成功结果、终态记录留存及清理互斥统一执行[文件架构的备份恢复合同](../../architecture/database/product-data-and-files.md)。本表是操作摘要，不另定义状态机；过期pending终结为failed并保留原因。D-01须将该矩阵映射为实际DTO/错误码；UNKNOWN不能换号，确认终结后由用户明确重新上传才用新号。

R2与PostgreSQL无跨服务ACID。Put或finalize失败/超时先核查真实请求/提交状态；并发原号可能已成功，不能catch后直接删可能被引用对象。对账可恢复或安全回收，不能对孤儿签下载，也不能按会员到期物理清理ready。

删除份数释放按文件架构唯一合同执行，代码前固定实际API/UNKNOWN语义并测试，不新增无依据抽象。
