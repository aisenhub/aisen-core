## 1. 完成结果与环境冻结

目标是证明同一正常Lens客户端在真实Core/Admin/隔离对象中完成整个业务，而非各模块单测分别通过。固定候选两仓HEAD、实际dirty差异/配置及依赖版本、HTTP origin/签名JWT环境、测试账号/产品、对象前缀、浏览器/硬件/限速及数据规模。

测试数据由Lens实际注册/兑换/反馈/备份产生，Admin用正式AAL2界面发码/直授/撤权/分诊。状态负例如必须由可信测试RPC准备，明确记录为fixture/故障注入，不假称是Lens用户点击；不以demo seed替代客户端请求。

开始前确认A～D问题关闭、schema/API与运行版本一致，旧服务/HMR/缓存未混入；隔离测试快照与QA清理边界明确。未知环境或正在变化的服务先停止取证，不用不稳定结果宣称PASS。

## 2. 必须完整走通的主路径

| 顺序 | 实际操作 | Core/Admin/本机断言 |
| --- | --- | --- |
| E-01 匿名Free基线 | 用隔离Lens浏览器打开已有本地项目、编辑/保存/基础导出、模板本地往返 | 不需Auth/RPC或上传内容；项目/素材/普通配置正常，现有未启用门槛不变 |
| E-02 注册与单向反馈 | 正常账号入口注册、Mailpit确认、登录；尚无成员时零图反馈 | auth.user真实，登录/反馈不建成员；Admin收件与当前用户/产品一致 |
| E-03 首次兑换 | 正式Admin发测试码，Lens兑换及刷新摘要/历史 | 合法兑换同事务创建唯一成员/Grant/核销，次数只一次，200业务结果准确 |
| E-04 云备份与恢复 | 同账号从真实上下文上传完整模板，列表/下载；个人模板安全变化后预览并恢复 | DB/对象/hash/份数一致，仅个人模板替换，当前项目/偏好/Key不变；非自动应用 |
| E-05 图片及Admin | 提交1/2图反馈，Admin四队列处理/查看私图/受控ZIP | 字节/hash/版本/权限/导出范围一致，无公开附件或用户回复中心 |
| E-06 到期/撤权 | Admin撤销当前Grant或使时段自然到期，Lens必要复核后尝试新增备份和取回旧文件 | 新增拒绝，准入合法的本人旧文件可查看/下载/删，历史保留，技术故障非Free |
| E-07 切号/离线恢复 | 在途请求与两账号/两标签切换、local登出、Core短暂断网再恢复 | 任务先收尾/明确取消，保险库锁定/会话Key释放；旧响应不串号，项目/密文保留，另一应用会话仍有效 |
| E-08 清理复核 | 按本包明确范围清理QA身份/反馈/对象/备份或保留必要证据 | 无误删长期本地数据/其他对象；未完成物理回收如实记录，秘密不进报告 |

真实用户闭环不要新加“测试专用成功按钮”。DEV预览、手工SQL造Grant/ready行可以辅助定位，不能代替这些主路径。

## 3. 安全与异常组合矩阵

| 维度 | 跨包场景 | 判断依据 |
| --- | --- | --- |
| 身份 | 无JWT/旧JWT、refresh撤销、未确认、blocked、普通AAL1/Admin AAL2和管理员撤权 | 当前可信状态及访问token实际窗口，避免要求signOut后全部JWT即刻401 |
| 产品/owner | 双账号、双产品、跨产品码/备份/反馈、left/suspended/产品停用 | 资源与准入在服务端，客户端过滤不授权；反馈成员例外单独验证 |
| 业务200 | allowed:false、ok:false、RATE_LIMITED、already-used、永久拒兑 | 不当HTTP成功或网络失败，码/Grant/成员副作用与合同一致 |
| UNKNOWN | 兑换首响、反馈回收站空查询、备份ready/删除确认丢失 | 各自同码/原号/真实状态恢复，不换号重建，不从空列表推失败 |
| 对象/DB | 两图部分成功、finalize超时、删除单侧成功、同号并发 | 当前引用/保护期/事务状态，已引用对象不误删，ready不可覆盖 |
| 时效 | 5MiB边界、20份多设备竞争、自然到期/已知撤权/最多15分钟快照 | 参数实测、有界读、服务端云操作实时授权，本地业务限制未顺便启用 |
| 本地一致性 | 模板恢复与另一标签修改/当前项目草稿/在途任务/密文 | 原存储/基线保护，恢复不改项目或凭据，失败保留可重试输入 |
| Admin/导出 | 切产品/筛选范围/敏感确认漂移、version409、缺图ZIP、在途撤权 | 已冻结范围和当前AAL2/RLS/最终审计，不导出未授权/半成品 |

映射API I-01～28、R-01～16、REV-DEC01/02/04/05/06、现行反馈安全与A～D用例。适用性必须逐项写明；R-14涉及SaaS实际功能策略等排除业务可验证Core职责不混入，但不能宣称AI/导出入口已实施。

## 4. UI、性能与不回归

本轮新增/改动的账号、权益、反馈、云备份页/对话框在代表数据/空/错误/等待状态检查中英、亮暗、键盘焦点、读屏名称、窄屏及缩放；界面只呈必要身份、标签、后果和反馈，无内部RPC/R2/调试信息。不因复用官方组件省略视觉/可达性验证。

在可复现生产构建环境比较接入前后Free冷/热启动、进入设置/账号、资格并发去重、列表/下载/图片/恢复交互、内存/请求量。记录原始指标和实际请求树；不固定轮询、不预取全部云正文、不每点击重查Auth。沿既有首屏/包预算门，新增性能退化要定位和修复，不能仅以bundle无变化说无退化。

回归优先：Lens账号正常入口、完整本地模板导入导出/个人保存/项目快照保护、项目保存/重新打开/基础导出、凭据锁定/密文保留；Core相关Admin/安全/数据库/Edge链。根据真实diff扩大必要回归，不为所有媒体/供应商耗时测试盲跑全仓；执行前已有无关失败单独对比，不隐藏由本次变更引入的失败。
