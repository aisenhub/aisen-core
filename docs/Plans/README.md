## 执行与删除

1. 计划只写目标、当前边界、具体动作、验收条件和真实进度，不复制业务架构或聊天/工具流水。
2. 不从历史计划恢复过期的 `plans`、公共功能额度、旧 RPC、旧原型 UI 方案。
3. **边开发边清理**：对应任务完成时立即核对活动计划、TODO 和相关索引。已完成的计划及纯交接/阶段流水须在迁移有效业务/安全约束与未完成项后删除，不能让历史过程变成开发的第二套要求。
4. 本地模拟、真实 PostgreSQL、真实签名 JWT/MFA、R2 和生产验收须分别说明范围；未运行不得记为 PASS。
5. 日常只清理本次影响范围；遇到多份计划互相冲突、旧方案堆积或阶段集中收尾时，使用 [按需过期文档清理提示词](../prompt/cleanup-outdated-docs.md) 复核全仓。交付前检查相关链接，明确已更新/无需更新的文档。
