## 1. 设计目标与非目标

### 1.1 实际操作者与成功路径

- **第一优先操作者**：只有**一名实际平台运营者**，使用 Admin 发行 AisenCore 自有码、给具体用户授权 Aisenlens Pro、管理产品/套餐与成员限制。保留最小管理员/恢复操作，但不虚构第二个已就位的运营人员或双人审批。
- **最重要业务旅程**：安全登录+一次必要 TOTP → 选择 Aisenlens 产品 → 查看/新建 Pro 套餐 → **按明确参数批量发码、首次成功响应内复制/主动下载明文、离开不能取回** → 查询批次/兑换/授权与审计。
- **安全/异常旅程**：身份过期/MFA 等级不够、账号被封禁/撤权、同一个 `request_id` 网络重试、保护最后合格管理员、套餐已被 grant/码引用被冻结、成员 `left` 封禁后仍恢复为 `left`。
- **性能旅程**：日常导航使用短期非权威 UI 资格与 TanStack Query 展示缓存；每个普通列表读/管理写只发送其主要业务请求，服务端在该请求内检查 JWT `aal2` 与**当前**管理员资格；无逐操作 MFA 弹窗或前置 `getUser`。

### 1.2 不在首版 Admin 的页面

不建设支付结算、自动订阅/退款、爱发电订单管理、共享 AI 代理管理、R2 私有文件内容浏览、Aisenlens 视频/项目管理、BI 实时图表、组织/部门/RBAC 编辑器、公开普通用户门户、完整自动账号删除/财务报表。**R2 用户备份的配置内容不能因管理员身份而被默认查看。**

## 2. 网站地图、推荐路由与页面交付清单

### 2.1 导航结构（信息架构 IA）

```text
Admin（受保护，未通过 aal2 不渲染业务壳）
├─ 工作台（仅快捷入口、最近允许的审计入口；不虚构实时业务统计）
├─ 产品与用户
│   ├─ 产品管理 → 产品列表 → 产品详情 → 创建/编辑/状态变更
│   ├─ 用户查询 → 受限查询结果 → 用户详情（最少字段）→ 平台限制
│   └─ 产品成员 → 成员列表 → 成员详情/事件 → 封禁/恢复
├─ 权益运营
│   ├─ 套餐管理 → 套餐列表 → 套餐详情 → 创建新版本/停用
│   ├─ 授权管理 → 授权列表 → 授权详情 → 手动授予/撤销
│   ├─ 兑换码 → 发行批次列表 → 新建发行 → 首次一次性明文结果
│   │          ├─ 批次详情/撤销 → 兑换码记录（**只显示安全列**）
│   └─ 兑换记录 → 只读兑换列表/详情
└─ 安全与审计
    ├─ 平台账号限制 → 封禁/解除封禁（危险动作）
    ├─ 管理员资格 → 最小列表/授予/撤销（M1）
    └─ 管理审计 → 只读列表/详情

业务壳外（不显示管理资源）：
  /login → /mfa/enroll 或 /mfa/challenge → /access-check
  /access-denied、/session-expired、/service-unavailable
```

首版侧栏**一级分组不超过四个**：工作台、产品与用户、权益运营、安全与审计。桌面可展开二级导航；窄屏使用带 aria-label 的抽屉。**工作台仅导向已存在的能力**，不增加为了显示 KPI 而新建后端统计接口。

### 2.2 UI 路由（候选，非已经实现的 API）

| UI 入口（候选路径） | 页面与默认任务 | 原有可信数据来源 | 业务操作界限 |
| --- | --- | --- | --- |
| `/` | 工作台：最近的可操作入口、手动快捷导航 | 静态导航 + 可选已批准安全查询 | 不显示未真实查询的“总注册量/销量” |
| `/login` | 邮箱密码登录 | Supabase Auth | 非 Admin/未 aal2 不进入其他受保护路由 |
| `/mfa/enroll`, `/mfa/challenge` | TOTP 注册/挑战/验证 | Supabase Auth 官方流程 | 因素秘密不持久化至 Admin 本地日志或业务库 |
| `/products`, `/products/:id`, `/products/create` | 产品列表/详情/创建与状态 | `products` 安全读 + 显式管理 RPC | 不通用 PUT/PATCH 保护表 |
| `/users`, `/users/:id` | 用户 UUID/有界邮箱查找/最小详情 | `admin-user-lookup` Edge + 合法关联摘要 | **不直查 `auth.users`**，不存在全量不受控邮箱检索 |
| `/memberships`, `/memberships/:id` | 产品成员列表/事件与暂停恢复 | `product_memberships`, `membership_events` | 不能以解封自动 rejoin |
| `/plans`, `/plans/:id`, `/plans/new` | 套餐读/创建新版本/停用 | `plans` 白名单读 + `admin_upsert_plan` | 被引用权益字段不能原地更改；更新全字段提交 |
| `/grants`, `/grants/:id`, `/grants/new` | 手动发放与撤销权益 | `entitlement_grants` + 管理 grant/revoke RPC | 有效期与永久独立明确 |
| `/code-batches`, `/code-batches/new`, `/code-batches/:id` | 批次读/发行/撤销 | `redemption_code_batches` + `admin_create_codes` | 明文仅本次首次成功响应 |
| `/codes`, `/codes/:id` | 单码安全状态列表/撤销 | `redemption_codes` 白名单列 + revoke RPC | **不能显示 `code_hash`、明文或历史导出** |
| `/redemptions`, `/redemptions/:id` | 只读兑换记录 | `redemptions` | 无编辑/删除入口 |
| `/restrictions`, `/admins`, `/audit` | 账号限制/管理员最小管理/审计 | 分别为受保护读 + 明确 RPC/只读审计 | M1 最后管理员保护和审计不可篡改 |

路由字段不直接等同 PostgREST 表名；`users` 为**虚拟 Resource**，`code-batches` 对应真实 `redemption_code_batches`。首次明文结果使用**发行页当前 React 组件的临时子状态**，**不创建**如 `/code-batches/:id/plaintext` 这样可回放/收藏的路由。

### 2.3 分阶段优先级（仍属于同一个 MVP）

| 级别 | 交付 UI 范围 | 目的 |
| --- | --- | --- |
| **P0 首先可操作** | 登录/TOTP/资格闸口、共同 Shell、产品+套餐读取、批次发行/只展示一次明文/结果不明、批次/码撤销、直接授予/撤销、基本错误处理 | 保障唯一运营者能安全开通 Aisenlens Pro |
| **P0 正式 MVP 发布前全部完成** | 产品/成员/用户/账号限制、套餐版本规则、授权/兑换记录、最小管理员/审计、安全/失败/响应式与无障碍验收 | 保证全部既定公共后台的管理闭环 |
| **P1 可延后但不替代 P0** | 可视化 KPI、跨产品 BI、导出全部用户、业务分析面板、复杂自定义列方案、批量编辑普通用户 | 防止范围膨胀 |

## 3. 页面设计如何使用统一 UI-G0 设计系统（候选尚未获品牌审批）

### 3.1 技术/设计系统

使用 React-admin 提供的 `Layout`、`Menu`、`Resource`、List/Show/Create 等标准组件，以及 Material UI Grid/Stack/Card/Dialog/Drawer/Button/TextField/Select/Snackbar/Alert；主题采用原生 MUI `createTheme`，不另建 Tailwind/Ant Design、独立表格框架或高成本可视化系统。开发前锁定真实 React-admin/MUI/SDK 版本，**不要复制老版本 Redux 等示例**。

设计语言：**简体中文优先、低噪声、操作优先**，表格是主角、重点危险动作清晰；“永久”、“到期”、“已撤销”、“left/已退出”不能只用颜色区分。示例品牌名为 **AisenCore Admin**，真实品牌 Logo/颜色与暗色策略未获用户审批。

**禁止在本文件与每个页面重复维护同一组像素值**；以下是使用 [UI-G0 全局规范](../architecture/applications/admin-ui-design-system.md) 的映射，不是新的 Token 来源：

| 本 D3-UI 使用位置 | UI-G0 唯一权威 Token / 模板 | 本阶段业务规则 |
| --- | --- | --- |
| AppBar、侧栏、主体容器、页面标题 | `AdminLayout`、`AdminPageHeader` 与 §3 App Shell | 侧栏只包含经批准的运营功能；MFA 入口不展示后台 Shell |
| 页面文字与数据 | `type.pageTitle/sectionTitle/body/formLabel/data/caption` | 用户 ID、日期、永久/撤销状态需要清晰可读 |
| 主题/间距/圆角/焦点/反馈 | `color.*`、`space.*`、`shape.*`、`StatusLabel` | 危险操作不可仅靠颜色、未经确认不假报成功 |
| 列表/详情/表单/异常 | `AdminListPage/AdminShowPage/AdminFormPage/AsyncState` | 字段/写 RPC/错误行为仍按 D3/F05 权威 |
| 首次发码明文/TOTP | `OneTimeCodeResult` / `MfaEntryTemplate` | 明文不可回取/本地持久化，`aal2` 不能由视觉门禁替代 |

### 3.2 布局断点与表格退化

**全局来源**：[UI-G0 §3.2](../architecture/applications/admin-ui-design-system.md#32-响应式与尺寸断点保证和-d3-ui-一致)。以下行为性描述继续有效；布局具体断点必须由**一个全局 Theme/页面容器**实现，不得各页面分别设断点。

- **≥1200 px**：完整固定/可折叠左侧导航、页头、横向筛选和表格；表格可按资源列宽布局。
- **768～1199 px**：缩窄/折叠导航，筛选条件可折行，数据表横向滚动但保留最重要标识/状态列。
- **<768 px**：顶部 AppBar + 可开关侧栏 Drawer，筛选折叠面板，详情逐组纵向卡片，危险确认使用窄屏 Dialog；不强行使多列宽表压缩至不可读。Admin 为桌面运营优先，手机只要求安全可读/查看和必要登录，不保证复杂发码/大表格编辑是主要运营体验。
- **320～375 px 极窄**：不能溢出页面壳或遮挡登出/MFA 表单；仅数据表容器内部允许横向滚动；重要按钮占整行，受限高风险批量操作可提示切桌面，但**不因仅前端隐藏而绕过后端安全**。

### 3.3 本地化与敏感字段显示

- 日期在 UI 按用户选择的本地时区显示，**详情可同时展示原 UTC 时间和时区**，避免 30 天/365 天时长误解；所有 API 字段仍按后端时区/ISO timestamp 权威值。
- 金额/成本/配额未获用户 U04 批准：**不展示虚构的费用/销量/剩余额度**。永久 grant 的 `ends_at = null` 展示“永久（无自然截止日）”，但 revocation/blocked 仍有效；不得误写成不可撤销。
- 列表 UUID 缩略显示只为排版，复制操作提供全 UUID，表单提交使用真实 UUID。邮箱等 PII 仅在准许的 Auth Admin Edge 最小返回范围显示。
- 哈希、JWT、Refresh Token、R2 签名 URL、MFA TOTP secret、备份配置内容不作为可查看字段；兑换码明文只可在刚发行成功的**临时结果**，被用户主动复制/下载时单独提示保管责任。

### 4.2 兑换码创建与一次性明文结果（M3）

```text
第一步：创建（尚未生成明文）
┌── 新建兑换码批次 ────────────────────────────────────────────────────┐
│ 产品 *              [Aisenlens ▼]                                  │
│ 套餐 *              [Pro 30 天 ▼]                                  │
│ 本批数量 *          [50]   （UI 校验须服从服务端已批准上限）           │
│ 每码可兑换次数       [1]    （缺省=1；显式 NULL 禁止）                  │
│ 码的失效时间         [日期+时间 / 明确时区；按精确 RPC 参数]           │
│ 用户收到码后授予期限  [30 天]（来自实际套餐/发行参数，非擅自推导）      │
│ [仅只读预览：有效值/默认值/受影响产品/成功后明文不可补发]              │
│                                               [取消] [确认发行]       │
└───────────────────────────────────────────────────────────────────┘

第二步：首次成功 created=true（只在当前存活组件中显示）
┌── 本次发行成功：明文仅此一次显示 ───────────────────────────────────┐
│ ⚠ 离开此页或刷新后将无法再次取回这批明文，请主动安全保存               │
│ [一段仅当前内存持有的码明文区域；非可搜索表格 / 非历史详情]             │
│                                        [复制本次码] [下载本次码]      │
│ 批次非秘密 ID：…                                                   │
│ [我已知晓，关闭并清除本页明文]                                     │
└───────────────────────────────────────────────────────────────────┘

响应超时 / created 状态未知
┌── 发行结果未确认 ──────────────────────────────────────────────────┐
│ 不自动重试创建，也不能声称已失败。                                   │
│ [按原 request_id 查询批次状态] [前往批次列表]                       │
│ 若已成功却没收到首次明文：仅可撤销旧批并经确认后用全新 request_id 重发    │
└───────────────────────────────────────────────────────────────────┘
```

- **固定不变量**：首次按钮生成并保存本次 `request_id`、规范化提交参数；相同逻辑请求网络重试保持原 UUID，**不能因组件 rerender 产生新 UUID**。F05 已确定规范化/NULL 语义由真实服务端裁定，UI 表单只是预检查。
- 明文不得进入 URL、browser history、持久本地存储、TanStack Query 正常查询缓存、错误 telemetry、network error log。允许用户**主动**复制/下载当前成功结果（本地下载是用户主动承担的安全存储），页面卸载、登出、刷新时清除内存状态。不得有“从历史批次重新下载明文”。
- 重复创建响应如 `created=false` 只可展示**非秘密批次状态**。列表里不显示码明文/散列；撤销操作必须基于实际返回状态。
- 发行数量显示“最多 100”**仅在 U08 被正式确认且后端真实启用该数值时**，目前 100/批只是候选，UI 不应写死。

### 4.3 套餐与权益冻结（M2）

```text
套餐详情：Aisenlens / Pro 365 天
┌───────────────────────────────────────────────────────────────────┐
│ 基本信息：plan_key / name / active / 是否被任何授权或发行码引用          │
│ 能力 Features：实际布尔键 (只展示经过校验的 JSON 与名称)                │
│ 额度 Limits：实际 numeric key / 单位 / 最大值                         │
│ 授权默认天数：365（示例来自套餐候选；以实际值为准）                       │
│                                                                       │
│ 当已被 grant 或发行码引用：                                             │
│ [已冻结：功能/额度/期限不能原地修改] [创建新套餐版本]                   │
│ 名称 / is_active 可按后端允许规则处理；停用不使已发旧有效码作废          │
│                                                                       │
│ 版本创建：表单必须显式携带全字段，不把缺失值转换 NULL 或空 JSON           │
│                                          [取消] [提交明确管理 RPC]      │
└───────────────────────────────────────────────────────────────────┘
```

“只修改名称或停用”也必须按 F05 合同提交完整受保护字段；UI 对已被冻结字段设置只读，**服务端同样必须拒绝违反冻结规则**。冲突返回 `STATE_CONFLICT` 时显示真实当前记录，并引导新建版本，而不是强制覆盖。

### 4.4 用户/成员双维度详情

```text
用户查询（经受保护 Edge，有界 UUID/邮箱条件）
  [查询类型 UUID | 有界精确邮箱]  [查询]  [返回结果/搜索范围说明]
      ↓
用户详情：UUID / 允许显示的邮箱 / 平台 blocked 状态
  ├─ 产品成员摘要（另查 RLS 允许的成员数据）
  │    ├─ Aisenlens ：active/left/suspended
  │    └─ 事件时间线（必要审计摘要）
  ├─ 产品授权（仅真实允许的本人/管理员范围）
  └─ [平台封禁/解封]（需要 reason、危险动作确认）
```

用户的 Auth 身份资料和产品成员是**两个不同数据源**，分页邮箱补全是有界 Edge 查询；如果邮箱搜索被最大扫描量截断，UI 必须显示“搜索范围不完整”，**不能显示确定不存在**。成员解封时从 `left` 被 suspend 的用户恢复后仍是 `left`，状态文案必须清楚；不得在管理端直接读产品私有内容。

### 4.5 TOTP MFA 登录门禁（MVP 必做）

```text
登录界面（无业务侧栏）
 [邮箱] [密码] [登录] [找回密码]
      ↓ Supabase Auth signInWithPassword
 JWT aal1 → [设置 TOTP 验证器 / 已有验证器输入 6 位动态码]
                └─ enroll / challenge / verify → 刷新或获取最新 aal2 JWT
                          ↓
                [校验当前管理员资格：admin_check_access]
                          ├─ active 且未 blocked → 后台 Shell
                          ├─ 非管理员/blocked → 拒绝页面（不可展示资源）
                          └─ Auth/网络失败 → 可恢复错误（不得假造角色/放行）
```

- TOTP enrollment 的 QR/secret 仅在官方流程当前界面短暂显示，不写持久业务日志；验证码需遮挡暴露、支持粘贴、错误提示不泄露身份资料；窗口/会话退出清理认证状态。
- **不是每次点“发码/翻页”再弹 TOTP**。只有新登录、当前 JWT 等级下降/会话失效、factor 需重验时，才进行必要的 challenge；正常管理表格/RPC 同请求检查已验 JWT 的 `aal2` + 实时管理员资格。
- MFA 丢设备的自助“关闭 MFA/直接通过邮箱绕过”**不纳入设计**；显示受控支持/恢复说明，真实恢复责任/身份在 U05 上线前定案，必须通过真实演练。

## 6. 页面操作合同与关键状态机

### 6.1 统一操作交互规则

1. 导航/筛选/排序使用 React-admin Resource 列表与 Provider，优先**单页一次主要数据请求**；可复用 TanStack Query UI 展示缓存，但 `aal2` 和管理员资格仍由每个服务器业务请求在 RLS/RPC/Edge 内判断。
2. 表单使用强标签、帮助文案、明确必填、逻辑字段组；`product_key`、UUID、数值上限的类型/合法范围由真实后端确认，UI 做**相同或更保守**的预检查，不能创建与后端不同的规则。
3. 一切修改只走显式业务 RPC 白名单；产品/套餐、封禁、授权、发码可使用 MUI Dialog 或独立页面，但不使用未经授权的通用 edit/delete Provider。
4. 危险动作要求重述**用户 ID/产品/套餐/授权或码批次**、受影响范围、`reason`（后端要求时必填）、撤销不可自动回滚警告；不设计并不存在的“多人批准”。
5. 成功仅以**后端确定提交成功的响应**宣告；需要失效相关列表/详情缓存并显示 audit 时间/安全 ID。取消操作不产生写 API；无法确认时显示“结果待核验”。
6. 页面切换前若有未保存表单，提示放弃修改；不可在组件卸载后继续展示码明文；失效 token/业务资格时清除敏感 UI 状态。

### 6.2 状态/错误语义矩阵（UI 可观察行为）

| 情形 | 显示内容与下一步 | 禁止行为 |
| --- | --- | --- |
| 初次加载 | 骨架屏/进度标识、保留已获许可的过滤上下文 | 以假数据代替网络响应，卡住所有导航 |
| 列表为空 | 清晰“当前范围没有记录”，可清除筛选 | 与无权限、服务器错误混为一谈 |
| `401` / Access JWT 失效 | SDK 按安全策略有限刷新，必要时回登录 | 捕获后假装查询成功、公开受保护数据 |
| `aal1` / MFA 不足 | 去官方 TOTP enroll/challenge；拒绝管理资源 | 只隐藏按钮但 Data Provider 继续查后端 |
| `403` / 资格被撤销/blocked | 清理管理 UI 资格快照并进入无权页 | 用旧导航缓存继续放行 |
| `409` / `STATE_CONFLICT` | 明确目标已变化、显示/重查当前记录；套餐建议新版本、M1 冲突说明 | 默认重试覆盖、客户端强制撤销最后管理员 |
| `429` | 服务限流，显示可恢复提示/等待建议 | 自动高频重复发码/无限循环 |
| `503/5xx` | 服务暂不可用，允许安全重试读操作；标记未确认 | 错把服务故障当用户 blocked |
| 超时 / 连接断开（写入） | 结果未知，按请求 ID 查原记录/安全状态；必要时人工撤销重发 | 为同一逻辑操作直接换 UUID 重放 |
| 已存授权到期/撤销 | 显示“已到期/已撤销/永久但当前被账号限制”，区分状态 | 把 `ends_at=null` 理解成有权绕过 blocked |
| 发码成功首次明文 | 当前内存临时显示，明确保存提示，复制/下载后留用户控制 | 保存到历史列表/telemetry 或点击详情再次显示 |
| 正在刷新/切换账号 | 隐藏此前账号的敏感资源和临时数据，重新初始准入 | 跨账号继续展示旧批次/用户资料 |
| 受控恢复未就位 | 提供人工运维恢复说明/联系方式占位；未确定时不能生产开放 | 前端“一键重置 MFA”绕过当前资格 |

### 6.3 交互中“确认取消”和“请求重复”细节

- 新建发码/直接授权/状态限制提交按钮在第一次发出请求后显示 pending 并防止双击；这一点**只提升 UX**，不能替代后端 `request_id` 唯一键与锁序。
- 表单切换套餐版本/用户时清除原操作预览，生成的新请求 ID 只能对应当前一组规范化有效参数。
- 若写成功后重拉列表暂时失败，保留**写成功有证据**的确认，但标记列表刷新失败；若写响应本身未知，不可展示“操作已成功”。
- 大批量发码 UI 不以默认 100/批将用户候选升级为真实硬上限；必须读取已冻结规则并与后端同源验证。

## 7. 性能、可访问性与安全视觉规范

### 7.1 低额外网络请求体验

- MFA 只在登录或真实 AAL 降级等需要时挑战；Admin 普通列表/编辑/发码不会每操作先 `getUser()`、`getAuthenticatorAssuranceLevel(jwt)` 远程请求及 `admin_check_access` 再写 API。JWT 由 SDK 刷新时可能确实访问 Auth，这**不属于可删除的安全依赖**。
- 长表分页/筛选 debounce 候选 250～400ms，按需加载用户详情，不为整页 N 个用户逐一无界调用 Auth Admin。邮件查询被限制时显示真实“仅扫描部分”。
- 不做显示为 0 的虚构报表。性能真值以后在目标 Free Project 测 Admin 正常数据请求次数、P50/P95、列表加载/筛选、TOTP challenge 次数、过度权限扫描与 Edge 调用。
- “长耗时操作”必须有可观察的 running/unknown/confirmed/failed 状态；前端成功 toast 不能只基于 Promise 发出或 optimistic mutation。

### 7.2 无障碍与键盘

- 目标为 **WCAG 2.2 AA** 相关可验证准则（目标，不是当前已达标证据）：表单 `label`/错误帮助文字关联、焦点可见、TAB 顺序按页面阅读、桌面全部核心任务无鼠标可完成。
- 对话框打开移动焦点至标题或首个可操作字段；关闭返回打开它的控件；高风险确认默认焦点不落在“删除/封禁/撤销”。
- 状态显示**文本/图标/颜色三重提示**；确保对比度、禁用态可解释；Alert/Snackbar 用 `aria-live` 合理宣告，避免重复刷屏。
- 不能仅靠颜色让用户识别“永久/已到期/已撤销”；UUID 复制按钮必须有清晰的读屏标签。
- MFA 输入与错误信息可键盘/粘贴，QR 应提供合法的文字设置替代路径且不持久化秘密；登录校验期间不自动跳过屏幕阅读器需要的错误反馈。

### 7.3 安全数据最小化

- 不在页面、日志、网络调试上报含 `service_role`、R2 access key、refresh token、code hash/MFA secret；浏览器 bundle 仅可含 Supabase Project 公开 publishable key。
- 兑换码明文**首次一次性短暂呈现**，用户主动复制/下载后自己保管；组件销毁/登出清理；不进入全局 Data Provider query cache、localStorage、history、URL。
- 高权限 Auth Admin Edge 查用户**先校验 JWT `aal2` 和当前数据库管理员资格**再使用 secret；前端不能因为页面显示一个用户 ID 就获得获取全部 Auth 资料的权限。
- 用户产品私有数据/R2 备份内容、AI Key、视频等不在公共 Admin 默认展示，非 UI 授权范围。

## 9. 前端工程交付顺序与可验证完成定义

**建议实现顺序（正式编码需独立用户授权）**：

1. **先通过 UI-G0 硬关口**：确认唯一主题/字体/间距/布局/组件、四类可见高保真参考（登录/MFA、兑换码、套餐、用户/成员）和跨宽度设计，并取得用户明确视觉签收/可追溯版号。**当前没有这些实物/签收，所以正式 `apps/admin` 编码被 BLOCKED**；之后再锁定 React-admin/React/MUI/Supabase SDK 兼容版本并建立最薄 `apps/admin` 壳。
2. 先做 Auth + TOTP enroll/challenge/verify + `aal2` 后真实 `admin_check_access`，验证 `aal1` 和非 Admin 直输路由/API 拒绝；切记失设备恢复真实责任。
3. 接入最小真实 Data Provider（安全只读）与管理 RPC Adapter（受控写入），验证真实 RLS/列 GRANT、PostgREST 函数签名/状态码，不能先用 `select=*` 假数据混过。
4. **优先落实发行批次与一次性明文 UX**，接着套餐/授权/撤销，随后产品、用户/成员、平台管理员及审计；各页伴随相应 D3-UI-X 和后端负向回归，不待最终才补权限测试。
5. 同步验证 1280px 与 375px 响应式、键盘焦点、不同网络条件及受限权限；按真实 P50/P95 与请求量评估低请求量目标。
6. Cloudflare Pages Dev/受限测试/正式生产环境、真实 SMTP/域名/MFA 恢复/操作审计/数据库备份演练与 U03 公众注册上线关口满足后才允许正式发布。

**MVP 完整 Admin 前端“完成”定义**：不仅 D3-UI 文档审核通过，而且上述 **P0 页面已实现 + 后端真实连接 + 明确授权的 UI 操作可执行 + 安全负向拒绝 + TOTP MFA 可用 + 码明文 M3 绝不泄露 + D3-UI-X01～X18 与 D4 对应逻辑验收真正留证通过 + 可部署使用**。只写了静态表格/UI 线框、可浏览的 mock 页面或仅登录成功，都不代表 Admin MVP 开发完成。
