# AisenCore｜按需清理过期文档（AI 执行提示词）

> **用途**：当文档开始堆积、阶段结束、架构发生较大变化，或项目所有者要求清理时，向 AI 明确发送“按 `docs/prompt/cleanup-outdated-docs.md` 执行文档清理”。**这不是每次开发都需要运行的流程**；日常文档即时更新和增量清理由根目录 `AGENTS.md` 强制规定。

## 给 AI 的任务

请在当前 AisenCore 工作区执行一次**全量文档有效性审查和过期清理**。目标是让下一位开发者/AI 只看到**唯一现行合同、真实工程状态及确实未完成的任务**，而不是历史过程。请实际检查并在必要时修改文件，而不是仅给建议。

### 必须遵循

1. **先确认当前状态，保护现有工作**：检查 `git status`，识别尚未提交的修改与未跟踪文件，不覆盖其他正在进行的开发。对照 `AGENTS.md`、`docs/spec/requirements.md`、`docs/architecture/`、`docs/Plans/TODO.md`、实际源码、迁移、配置和测试证据。Git 历史可追溯已跟踪内容，但**未跟踪的唯一文件不能依赖 Git 恢复**。
2. **逐份审查所有项目文档与有效引用**：覆盖仓库根目录、`docs/` 各专题（包括 `Plans/`、`development/`、`interaction-benchmarks/`、`prompt/`）及代码目录下的 README/设计说明；检测失效链接、缺失文件、重复的规则、过时版本/路径/端口、旧授权状态、旧实现假设、被推翻的方案和虚假完成标记。必要时检查非 Markdown 的规则/配置文档。
3. **按权威更新，禁止旧方案回流**：当前需求只在 `spec/` 定义；长期业务、安全与技术约束放在 `architecture/`；可复用开发与测试规范放在 `development/`；正在执行的阶段与真实未完成项放在 `Plans/`。如果文档与真实代码、数据库迁移或验证结果不符，应核实事实和现行用户决定，再修订正确的权威文件及引用，不能盲信任意一方或让历史候选优先于现行合同。
4. **及时移除过程污染**：删除或合并已经完成的执行计划、旧交接、过渡草案、被取代的审核快照、重复状态台账、已无实施意义的示例/原型迭代说明和空占位目录。先把其**仍然有效且未在其他位置保存**的需求、安全边界、接口不变量、真实测试用例、故障复现证据与未完成事项转移到所属权威文件；再删除原过程文档。**对是否过时存在疑问时先核实，不按日期或篇幅直接批量删除。**
5. **精确区分进度**：已选定/已设计/已编码/本地运行 PASS/真实 JWT 或云服务 E2E PASS/生产上线是不同状态；严禁将原型 PASS、合成 JWT 的 RLS 测试、文档评审和真实系统验收混为一谈。将实际未完成事项合并回唯一 TODO，已完成任务从 TODO 移除。**未获准的功能不得因为出现在旧原型或计划中就被写成必须实施。**
6. **检查引用和一致性**：更新 README 与各主题索引，检查**全部有效本地相对链接**是否指向存在的文件；搜索已删除的文件名、已废弃接口/表/参数和互相冲突的“当前状态”。运行 `git diff --check` 和与此次变更直接相关的轻量检查；修改到可执行代码时才运行对应测试。不要在文档清理任务中无故改动数据库、生产环境或重造开发框架。
7. **明确输出和权限边界**：报告删除/合并/保留/更新的文件、清理的核心冲突、仍有歧义的事项以及链接/测试检查结果。没有实际执行的验证明确标为 NOT RUN。未经项目所有者明确要求，**不提交或推送 Git，不自动合并分支，不接触生产/第三方云服务**。对有效迁移、测试、当前活动计划、正式合同和未跟踪唯一证据采取保守保护原则。

### 完成标准

文档入口足够简洁；长期规范与真实实现不矛盾；没有引用失效或“已删除但仍被当作现行依据”的文件；TODO 只剩真实未完成事项；完成的过程文档不继续污染开发输入；本次操作可通过 Git diff 复核。

> 日常开发不必每次重复以上全仓审核，但必须按 `AGENTS.md` **边开发、边同步文档、边清除直接相关的过期内容**，不能等到下一次专项清理才修正已经失效的描述。
