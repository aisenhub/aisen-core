# 产品业务数据与文件存储专项架构

> 状态：公共 PostgreSQL 和 R2 技术选型及数据归属原则已确认；各产品业务库拓扑和 R2 具体规则待讨论

## 数据类型及边界

| 数据类型 | 示例 | 当前归属 |
| --- | --- | --- |
| 平台公共数据 | 用户身份、产品目录、产品成员状态、产品级会员权益 | Supabase Auth + **Supabase 托管 PostgreSQL** 公共身份/产品/成员/权益核心 |
| MVP 公共权益与兑换 | 套餐、授权、兑换码哈希、兑换记录 | **公共 Supabase PostgreSQL**，与兑换核销保持同库同事务，见[权益数据约束](./entitlements-and-redemption-constraints.md) |
| 后续支付渠道数据 | 订单、续费、退款事实 | 渠道进入实施阶段时再决定位置、对账和一致性；不影响 MVP 授权表位置 |
| 产品结构化业务数据 | 项目、任务、聊天、生成记录、状态 | 由具体 SaaS 自己管理，数据库实现待定 |
| 云端文件本体 | 上传图片、视频、PDF、生成结果 | **Cloudflare R2** 文件对象存储 |
| 文件元数据 | 属主、产品、关联项目、对象 Key、大小和时间 | 对应产品的结构化业务数据库 |
| 本地业务与文件 | 本地视频、切片、客户端 AI 结果 | 留在产品客户端，详见[本地优先专项](../applications/local-first.md) |
| 日志和审计 | 公共后台操作、各产品使用事件 | 按平台与产品职责分开，细节待确认 |

**业务数据库**保存可查询与关联的数据记录；**R2**存储文件对象本身。文件在 R2，并不意味着文件属主、权限及项目关系无需数据库记录。

## 独立边界

- 各产品业务逻辑、数据访问权限与生命周期独立。可以逻辑隔离，也可以在确有必要时物理隔离。
- **产品数据独立不意味着必须一产品一 Supabase Project**。是否同库不同表/Schema、独立库或独立服务，等具体产品需求明确后比较。
- 统一身份及产品权益等公共结构化信息使用已选定的 Supabase 托管 PostgreSQL，**不要求各 SaaS 把自身业务数据放在同一个公共数据库中**。
- 私有文件上传下载需要由可信授权流程按产品和用户限定访问；R2 不自动替代业务层权限管理。
- 云端型产品可以接收用户主动上传的业务文件；不受本地优先拉片产品“只上传配置”的限制。
- **云端文件或备份配额属于首期确认的权益能力**，但各产品可以按需启用。公共 `plans.limits` 定义与返回上限，实际已用量由拥有文件元数据的产品计算并在业务操作中执行检查；计量周期、超限与回收策略按产品确定，MVP 不建立公共用量账本。

## Aisenlens 私有配置备份：长期可信边界（G-03 / M-03 / X-02）

**DEC-02 A 已获批准：首发 Aisenlens 小体积非敏感配置/模板 JSON 由受保护 Supabase Edge Function 接收、白名单/摘要校验并使用服务器受限 R2 凭据创建 final 对象**；恢复下载仍经实时鉴权获取短期 R2 授权后由客户端直接读取字节。**其他大文件和通用私有文件原则上仍客户端直传 R2**，不得将 Edge JSON 例外扩大到视频、项目或 AI 输入/结果。此为**已批准架构、NOT IMPLEMENTED**，Cloudflare Worker 不是该路线的必需部署组件。

1. **数据白名单**：仅用户主动选择的非敏感配置/模板字段、明确 schema/版本/大小；视频、项目、时间轴、AI 结果、用户 AI API Key、JWT/Token 禁止备份。U09 字段和大小限制未定，256 KiB 只是候选。
2. **身份与属主**：真实用户 JWT、blocked、active 产品/成员、当前备份权益及对象属主均在可信端校验；每次新的短期上传/下载签名和列举/恢复都重新鉴权，R2 key 不构成权限。
3. **final 不可覆盖**：Aisenlens JSON 客户端仅可 HTTPS POST/PUT 到**受保护且强制大小上限**的 Edge；浏览器/本地客户端不获得该备份 final/staging R2 写凭据。Edge 在内存/受控流中校验 JSON schema、字节数、可信 SHA-256、用户/产品属主与当前权限，创建**唯一 final key**并采用当前 R2 SDK 实测可用的条件写，禁止覆盖旧 ready 对象；ETag/HEAD 不能替代 JSON 内容校验。
4. **DB 配额与请求幂等**：以用户、产品、request_id 的受控作用域识别相同请求及冲突，在数据库事务内锁定配额和 pending 预留。可用空间的**已占用量 = ready 真实字节 + 尚未过期 pending/真正 verifying 的预留**；过期预留查询时即时释放，但**不代表 R2 中的残留对象已经物理删除**。
5. **跨系统失败恢复**：R2 成功但 DB 未 ready 时，孤儿 final 不得向用户签发下载，需对账完成或隔离删除；DB ready 已完成但 HTTP 响应丢失，同 request_id 返回原结果，不创建第二份或重复计费；删除单侧成功需有幂等 deleting/deleted 重试。pending→ready/failed、必要时 deleting→deleted 即最小状态机；verifying 非必要不引入。
6. **手动恢复与私有性**：备份永不自动成为分享资源；用户必须手动选版本、预览差异、确认后仅替换选择类别，并具备局部失败回滚。U10 版本数/保留期尚未批准，短期已签 URL 允许的撤权时差需要限 TTL 和实测。
7. **审计/清理**：非秘密 request_id、对象逻辑 ID、所属产品与状态足以追踪单侧故障/超时预留/孤儿清理；必须有实际清理执行者、告警和人工最小权限恢复，不记录明文 JSON、预签 URL 或 Auth 秘密。

| 失败注入 | 正确恢复，不得宣称 |
| --- | --- |
| Edge 已预留配额但客户端断网/上传体未完整到达 | pending 在过期后逻辑释放，清理未完成/孤儿 final（若存在）；不永久锁配额 |
| R2 写入成功但 DB ready 失败 | 保留不可下载状态，按 owner/key/hash 对账完成或安全删除 |
| ready 提交成功但响应丢失 | 同 request_id 查询原状态；不能重建对象、重复计费 |
| 多设备并发同 request_id | 同配置幂等，不同配置冲突；唯一键/锁防超额 |
| 旧请求重放 / blocked 或权益撤销 | 旧上传请求不能覆盖 final，可信 Edge 在上传/提交前实时复核；新下载短 URL 必须重新鉴权，已签 URL 存在到期前风险窗口 |
| 删除 DB/R2 单侧失败或清理定时任务不可用 | 保持可重试状态、持续对账与告警，不能隐瞒孤儿物理成本 |

**已批准的状态机（DEC-02 A）**：Edge 在受保护 DB RPC 中创建或读取幂等 `pending`/配额预留 → 校验 JSON 并由服务器条件创建唯一 R2 final → 受保护 RPC 在**再次核验当前授权与预留**后提交 `ready`/审计 → 返回最小安全对象摘要；同 request_id 重试先查询 DB 真正状态。Edge/R2 与 PostgreSQL **没有分布式 ACID**：R2 成功而 DB failed 则隔离 final 并由受控对账者恢复/删除，DB ready 而 HTTP 失败按原 request_id 幂等返回；对账和过期对象物理清理必须真实配置。白名单具体字段、单文件最大字节、版本数、留存期限仍属 U09/U10 待实施参数，**256 KiB 非本次凭空批准的硬值**。R2 条件写能力、权限/费用与 REV-M03-01～08 实测目前全部 NOT RUN。

## 产品成员退出与业务数据生命周期

成员退出只变更公共成员状态，**不自动删除** SaaS 业务数据、R2 备份或本地文件，也不自动撤销权益。各 SaaS 对自己的数据保留、删除、恢复和导出政策负责；重新加入并不保证已删除的数据可恢复。独立删除及注销请求需跨产品协调，短期文件访问凭据可能存在有效期内的撤权延迟。

业务规则以[成员生命周期](../domains/membership-lifecycle.md)和[平台账号生命周期](../domains/platform-admin-and-account-lifecycle.md)为准，本文只定义数据归属。

## 不做

- 不将所有产品业务内容塞进公共账号/权益数据库。
- 不为了形式上的独立性提前建立大量数据库或 Supabase 项目。
- 不预定每个 R2 Bucket 只服务一个产品，也不默认允许匿名访问私有对象。
