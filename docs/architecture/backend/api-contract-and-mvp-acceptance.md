# 统一用户 API 契约收口与 MVP 验收清单

> 状态：MVP **逻辑接口规范、最小数据契约、错误语义和验收标准**。示例 URL/字段/状态码可作为将来实现候选，非已实现路由或 OpenAPI/SQL；客户端 UI 文案与具体限流/超时数值仍按实际产品调整。

## 1. 复用优先和接口集合

身份注册/登录/会话刷新/确认邮件/密码重置直接复用 **Supabase Auth**；不额外定义 `/login`、`/refresh` 或第二套产品 JWT。

| 分组 | 逻辑方法 | 调用者 | 是否写入 |
| --- | --- | --- | --- |
| 产品目录 | `ListAvailableProducts` / `GetProduct` | 匿名/已登录（受限公开字段） | 否 |
| 本人身份/成员 | `GetMyProducts`、`GetProductAccess` | 已登录用户 | 否 |
| 公共准入 | `EvaluateProductAccess` | 经可信认证的用户请求；独立 SaaS 可信后端可转发其用户 JWT | 否 |
| 本人成员 | `EnsureMembership` | 首次合法业务接入 | 仅无记录时创建 |
| 本人成员 | `LeaveProduct` / `RejoinProduct` | 本人明确操作 | 是 |
| 内部 Admin | `SetProductStatus`、`SuspendMembership`、`RestoreMembership`、相关成员/审计查询 | 已通过服务端管理员校验 | 是/只读 |
| 公共账号 | `GetMyAccountStatus` / `RequestAccountDeletion`（账号专项的逻辑入口） | 本人 | 查询/受理；不直接等价完成删除 |
| 独立权益/计量 | `GetProductEntitlements`、可信额度扣减/兑换/支付事件处理 | 对应合法业务流 | 归权益专项，不并入成员写入 |

首版可把多个**逻辑方法**合并部署为少量 Edge Functions，**不按每个逻辑操作强制创建一份独立服务**。不同 SaaS 只需对接公共身份/成员/权益契约，各自业务 API 保持独立。

## 2. 输入身份与授权模型

普通用户请求：`Authorization: Bearer <user JWT>`，公共服务验证签名、过期、签发来源等；从可信令牌获取 `user_id`；用户请求体不得指定另一个操作者。目标产品以受校验的 `product_key` 传入，产品不能自行宣称管理权限。SaaS 可信后端代用户转发 JWT 不代表已获得平台管理员或服务机器身份。

管理员请求：仍有有效用户身份，另经当前可信的 `platform_admins` 管理资格查询；对目标产品、动作、状态进行独立权限检查。产品业务后端不得获得整个平台的高权限密钥；后台无用户场景确有需要时才设计限定产品/操作的机器凭据。

公共授权判定是“当前用户 × 当前产品 × 所需能力”的无副作用快照，不能当成另签发的许可票据。当前状态检查顺序：认证与平台全局限制 → 产品存在/运行状态 → 当前产品成员 `active` → 所需权益/额度 → SaaS 自己的具体资源/业务权限 → 可信计量与执行。无需为每步单独发 HTTP 请求，可在同一次可信请求中复用合理的新鲜结果。

## 3. 候选请求与响应语义

逻辑 `EnsureMembership(product_key)`：只接收已验证用户身份与产品标识；返回当前 `membership_status=active` 和布尔 `created`，已 `left/suspended` 禁止隐式恢复。其调用发生在首次真正需登录的合法产品业务，而非注册、登录、支付回调、产品展示或只读查询。

逻辑 `GetProductAccess(product_key)`：返回受限的 `product_key`、`product_status`、`membership_status`（尚未加入可表示 `none`）、`can_access_member_services`、`reason` 和可选 `evaluated_at`。查询没有副作用；非当前用户的状态不得泄露。

逻辑 `EvaluateProductAccess(product_key, capability)`：返回 `allowed`、`reason`、`evaluated_at`、适用的产品/成员状态（按最小需要）。不返回订单秘密、管理员封禁原因、他人信息或业务资源内容。`allowed=true` 仅表示公共准入与所要求公共能力符合，不表示对任意项目/文件有权限，也**不**自动扣减配额。

成员变更成功返回可信的新状态；不需要向客户端透露 `pre_suspend_status` 或内部管理原因。管理员暂停和恢复从**当前数据库**取得旧状态及封禁前状态，成功更改当前状态与一条成员事件在同一事务内提交；重复无状态变化请求不重复写事件。

## 4. 标准 HTTP 与错误模型

- 成功响应优先用正常 HTTP 状态 + 简洁 JSON，不强制全局 `success/data` 双包装；真正创建可使用 201，已存在/成功读取 200，具体选择将来统一。
- 错误响应优先参考 **RFC 9457 Problem Details**（`type/title/status/detail`）并扩展稳定 `code`；不能依赖任意语言文案作条件判断。
- **401**：未认证或令牌无效；**403**：有效身份但不满足准入/权限；**404**：确实不存在或为了防资源枚举不公开存在性；**409**：请求的状态转换与当前状态冲突；**400/422**：输入不合法；**429**：限速；**503**：依赖公共授权服务暂时无法提供可信结果。

| 稳定业务代码（候选） | 语义 | 客户端建议 |
| --- | --- | --- |
| `AUTH_REQUIRED` | 身份/令牌不合格 | 使用 Auth 现有登录或刷新流程 |
| `ACCOUNT_RESTRICTED` | 平台全局业务访问受限 | 不自动创建/解封产品成员 |
| `PRODUCT_UNAVAILABLE` | 产品未开放/暂停 | 不尝试隐式加入 |
| `MEMBERSHIP_REQUIRED` | 尚未加入需登录产品 | 由合法首次业务触发 ensure |
| `MEMBERSHIP_LEFT` | 已主动退出 | 提示用户明确 rejoin |
| `MEMBERSHIP_SUSPENDED` | 产品成员被限制 | 禁止客户端解封 |
| `ENTITLEMENT_REQUIRED` | 当前能力缺少 Pro 或有效权益 | 允许正常 Free 能力 |
| `RESOURCE_FORBIDDEN` | 产品资源访问权限不足 | 不泄露其他用户内容 |
| `STATE_CONFLICT` | 非法/竞争状态转换 | 读取当前状态后交互 |
| `RATE_LIMITED` | 超过限制 | 有界退避及 `Retry-After`（如有） |
| `SERVICE_UNAVAILABLE` | 无法取得可信公共授权 | 云端新受保护操作不默认放行 |

访问 `left` 时返回 403，尝试非法状态转换时可使用 409；错误码与 HTTP 状态的精确映射必须跟随**操作语义**，不是每种错误一律固定同一个 HTTP 状态。

## 5. 幂等、并发、撤权与服务故障

- `EnsureMembership`：`UNIQUE(user_id,product_id)` + 原子创建；重复 `active` 无新事件，`left/suspended` 不自动复活。
- `LeaveProduct`、`RejoinProduct`、管理员封禁/解封：在当前状态条件下原子执行；封禁前状态只由可信端保存，旧并发请求不能覆盖新封禁。
- 请求超时后不得断定失败，应先读取当前状态再安全重试；会员权益核销、兑换码与支付事实的幂等另外按各自业务唯一键处理。
- 客户端缓存仅用于 UI；新的云端关键操作由可信服务端复核当前产品/成员/权益状态，不要求每次简单 UI 读取跨服务调用。不设 Redis 跨请求授权缓存或自行签发产品 JWT。
- 账号/成员封禁或产品暂停后的下一次可信检查应拒绝新受保护操作；已开始任务和先前短期 R2 URL 的撤权边界另外按产品风险定义。本地 Free 离线继续可用。
- 429/503 采用有限重试，不因鉴权服务故障“默认通过”；503 不应显示为“用户被封禁”。

## 6. MVP 验收用例（实施前标准，不代表已经运行）

| 序号 | 用例 | 必须满足的结果 |
| --- | --- | --- |
| I-01 | 普通用户注册/登录后只查看产品 | 无跨产品自动成员创建 |
| I-02 | 云端合法首次业务接入 | 后端代用户调用 ensure，原子创建唯一 `active` |
| I-03 | 本地匿名 Free | 无登录、无成员、无公共联网依赖 |
| I-04 | 本地首次 Pro 或私有备份 | 本人 JWT 直调 ensure；后续按在线权益复核 |
| I-05 | 两设备同时首次加入 | 只有一条当前成员和一次成功 join 事件 |
| I-06 | 退出后登录、查询、支付回调或 ensure | 保持 `left`，不隐式 rejoin |
| I-07 | 用户明确 rejoin | 同一成员记录回 `active`；历史试用/Pro 不重置 |
| I-08 | 从 `active` 封禁再解封 | 回 `active`，不自动复活过期 Pro |
| I-09 | 从 `left` 封禁再解封 | 回 `left`，仍需用户重新加入 |
| I-10 | 重复封禁/并发旧请求 | `pre_suspend_status` 不被覆盖，旧请求不能解封 |
| I-11 | 产品暂停 | 不允许新受保护操作，不批量变更成员 |
| I-12 | 产品恢复 | 已退出/被封禁成员和过期权益不自动恢复 |
| I-13 | 普通用户访问他人成员/审计 | 数据库权限与 API 都拒绝 |
| I-14 | 用户尝试直接更改成员/管理员字段 | RLS/GRANT 拒绝 |
| I-15 | 操作成员状态成功但事件写入失败 | 整体事务回滚，无不一致状态 |
| I-16 | JWT 有效但当前已封禁 | 新关键授权请求拒绝 |
| I-17 | 产品 A 封禁、产品 B 正常 | B 不受 A 成员限制影响 |
| I-18 | 平台级封禁 | 所有产品新的受保护公共准入拒绝；成员原状态保留 |
| I-19 | 查询缓存显示旧 Pro、真实授权已失效 | 云端新 Pro 操作拒绝 |
| I-20 | SaaS 无目标资源权限但有 Pro | 业务服务拒绝访问他人资源 |
| I-21 | 公共授权超时或 503 | 新云端受保护操作不放行，展示不可验证而非封禁 |
| I-22 | 成员加入成功但 SaaS 业务库失败 | 公共成员保持，产品业务初始化可重试 |
| I-23 | 密码找回/未验证邮箱/跨域回调失败 | 使用 Supabase Auth 安全恢复，无隐式加入 |
| I-24 | 在产品 A 登出（local），产品 B 会话 | A 正常退出，不误触发 B 会话撤销 |
| I-25 | 用户发起账户注销 | 受理与实际清理有明确区分，不提前声称全系统已删除 |
| I-26 | 管理员被撤销管理资格 | 新管理 API 不靠旧 UI/JWT 声明放行 |

验收还应至少覆盖 401/403/404/409/429/503 区别、请求超时状态确认、适当的隐私/资源不可枚举检查、RLS 正反向测试；以上为**测试场景规格**，没有创建自动测试或运行数据库。

## 7. 交付边界与尚待实施决定

本领域逻辑架构可以视为 MVP 方案闭环；**并不**意味着已完成实际安全测试、上线合规确认或可直接实施。进入开发前需最终确认：路由/Schema、具体 Auth/Edge Functions 认证包装版本、受限事务实现与 SQL、RLS 逐表策略、管理员引导与密钥保管、邮件服务/回调域名、请求超时/限流参数、完整用户注销和保留政策及长任务/R2 撤权时效。

不建独立 OAuth/SSO 服务器、通用策略引擎、二次 JWT、跨库事务服务、复杂审计平台、Redis/事件总线，除非新需求和性能证据明确支持。
