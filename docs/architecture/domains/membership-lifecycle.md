# 产品成员生命周期、权益与数据保留

> 状态：成员加入、退出、封禁、恢复与数据/权益独立的业务规则已确认；保留期限、撤权时效、删除执行机制与自动续费渠道操作尚待细化。

## 1. 状态模型

- **不存在记录**：从未加入当前产品，不是数据库成员状态。
- **`active`**：正常产品成员；仍需经过产品状态、Pro 权益和业务资源权限检查。
- **`left`**：用户主动退出；不能访问要求成员资格的受保护产品服务。
- **`suspended`**：平台可信管理员暂停/封禁；普通登录、兑换、支付或重新加入均不能解除。

首版只采用三个持久化状态，不增加 `pending`、`expired`、`invited`、`banned` 等状态。暂停原因和恢复条件是独立管理信息，不把 Pro 到期当作成员到期。产品 `suspended` 与成员 `suspended` 是不同维度。

## 2. 状态转换

| 原状态 | 触发 | 目标状态或结果 |
| --- | --- | --- |
| 无记录 | 首次认证使用当前产品的需登录服务，产品允许加入 | 原子且幂等创建 `active` |
| `active` | 同一用户重复登录、重复加入、请求重试 | 保持 `active` |
| `active` | 用户明确退出 | `left` |
| `active` 或 `left` | 有权管理员暂停/封禁 | `suspended` |
| `left` | 用户普通登录、应用启动或兑换 | 保持 `left` |
| `left` | 用户主动确认重新加入且通过校验 | 恢复原记录为 `active` |
| `suspended` | 普通登录、重试、兑换、申请加入 | 保持 `suspended` |
| `suspended` | 有权管理员明确解除限制 | 恢复本次封禁前的状态：此前为 `active` 则恢复 `active`，此前为 `left` 则恢复 `left`；不自动恢复失效 Pro |
| `suspended` | 用户请求退出/删除个人数据 | 不自助解除封禁；数据请求仍单独受理 |

重新加入恢复同一条成员记录而非创建新的关系；首次加入时间不重置，当前状态由 `product_memberships` 保存，关键变更同事务记入 `membership_events`，不靠重放事件推算当前状态。具体约束见[数据库逻辑约束与最小审计模型](../database/database-constraints-and-audit.md)。封禁与重新加入/重复创建竞态须在可信服务端以最新状态的原子条件更新处理，确保旧请求不能覆盖新限制。管理员恢复需记录执行者、理由和时间；**封禁时应可靠保存封禁前的 `active` 或 `left` 状态，重复封禁不得覆盖这个值，解封不得无意把已退出成员改为 active**。一般用户重新加入 `left` 不需要默认管理员审批，但必须有明确的用户操作。具体 API 逻辑详见[公共 API MVP 与 SaaS 接入](../backend/public-api-and-saas-integration.md)。

## 3. 退出与数据删除分离

**退出只改变成员资格**：`active → left`，不自动注销平台账号、不删除成员审计、不撤销原会员授权、不取消订阅、不退款、不删除云端项目/R2 备份或用户本地文件。成员退出后的受保护请求应拒绝；查看自身成员状态、历史权益、发起删除请求或取消续费等必要账号操作应保留合适途径。

- 本地优先：本地视频、项目、切片、AI 结果与 API 密钥不因退出由平台删除；原本可离线的免费功能继续可用；私有配置备份保留，但云端备份等受保护能力按成员状态拒绝。
- 云端 SaaS：业务项目、文档、任务和上传文件不因退出立即清空；退出期间正常受保护业务访问停止，由产品遵循自己的保留/删除政策。
- 混合 SaaS：本地数据继续本地管理，云端业务和同步数据按产品保留规则处理；重新加入不承诺自动解决同步冲突。
- 用户**单独提出的数据删除/账号注销请求**必须进入独立流程，考虑各产品数据库、R2、备份、副本、必要的财务记录和适用法律要求；不能假定删除 Auth 用户就完成所有系统清理，也不能凭“退出不删除”无限期保留所有个人资料。
- 数据可由产品区分“保留中 / 清理中 / 已删除”，这是产品数据生命周期，**不是公共成员状态**。保留期限、恢复窗口、删除工作流与用户通知在具体产品上线前确定。

## 4. 退出与历史权益分离

| 授权/计量 | 退出期间 | 明确重新加入后 |
| --- | --- | --- |
| 月付/年付有效期 | 自然流逝，不默认冻结或延长 | 未到期且未撤销，则继续剩余权益 |
| 一次性永久购买 | 非周期授权事实继续保留 | 授权仍有效且符合范围时恢复使用 |
| 免费试用 | 原试用时间继续流逝 | 不因重新加入重新发放试用 |
| 次数/数量额度 | 不因退出自动重置 | 依原周期/计量来源核算 |
| R2 云端存储/备份额度 | 已保留文件按相应规则计量 | 按剩余额度及保留数据计算 |
| 已退款/撤销授权 | 保留必要历史但已失效 | 不因重新加入恢复 |

**权益存在不代表访问允许**。实际使用需同时满足账户、产品、成员及具体权益/业务授权条件。退出/封禁不删除订单或支付事实。**用户主动兑换**与无成员/`left`/`suspended` 的确定分支、**管理员授予**和未来支付回调的差别，以[计费权益 §5](./billing-and-entitlements.md#5-授权与产品成员状态的关系唯一权威)为唯一权威；不得以授权到账作为隐式重新加入或解封的依据。

退出产品**不等于取消自动续费**。未来有实际自动续费渠道时，应单独提供取消订阅的必要路径并清晰告知，避免用户以为退出即停止扣费。退出期间合法产生的续费事实可以保留，但不能自动恢复成员状态。永久授权的具体撤销情形、停服补偿与退款仍按专项规则。

## 5. 产品与成员状态组合

- 产品 `draft` 时普通用户不得自动加入。
- 产品 `suspended` 时停止新的普通加入和需该产品有效运行的受保护服务；**成员记录、会员、订单和产品数据状态不随产品停用批量改变**。
- 产品恢复 `active` 不自动解封个人 `suspended` 成员，不使到期的 Pro 再生效。
- 对于本地优先软件，平台无法保证离线中的已有本地操作立即停止；成员状态要在下一次受保护联网校验时才能生效。与会员无关的本地免费功能不应被无故禁用。
- 停服期间的权益有效期默认不自动调整；是否补偿属于后续计费政策。

## 6. 并发、安全及异常

1. **双设备首次加入 / 重试超时**：`user_id + product_id` 保证唯一当前记录；创建与返回幂等，不能依赖前端“先查再插”。
2. **退出与业务请求并发**：确定可信服务端状态生效点；退出后拒绝新的受保护请求，已经开始的长任务如何处理取决于产品。
3. **封禁与重新加入并发**：状态更新使用可信、原子及条件检查，旧请求不能覆盖新封禁。
4. **服务不可用**：不能在无法核验成员时默认放行新的云端受保护操作；本地免费能力继续遵循离线原则。
5. **短时文件授权**：先前签发的 R2 临时授权 URL 可能在有效期内仍可用；实际撤权时效和签发期限需单独设计。
6. **重新加入与数据清理并发**：重新加入不默认取消已进入不可逆阶段的清理，也不保证恢复已删除数据。
7. **用户账号失效或全局限制**：不得新建/恢复成员；各产品成员记录和历史授权不因此直接删除。
8. **成员状态变化与 JWT 缓存**：已有登录令牌不代表成员仍有效；安全敏感的服务端操作应核查可信的当前成员状态，不能依赖前端缓存或用户可改写的元数据。

平台管理员、全局账号限制与注销边界见[管理员与账号生命周期](./platform-admin-and-account-lifecycle.md)，账户生命周期独立于每个产品成员状态。
